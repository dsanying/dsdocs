## 本地运行

准备 Node.js 26 和 pnpm 12.9.0，在项目根目录执行：

```bash
pnpm install:all
pnpm build
pnpm manage
```

另开一个终端运行读者端：

```bash
pnpm preview
```

默认管理入口为 `http://127.0.0.1:5182/`，本地读者入口为 `http://127.0.0.1:3200/docs`。首次管理登录使用 `admin/admin`，随后必须修改用户名和密码。

全新的内容数据库会自动载入这组教程。若希望从空站点开始，在首次启动管理端前设置 `DSDOCS_STARTER=none`。已有站点不会因为重启或升级而覆盖内容；删除初始文档后也不会自动恢复。

## 配置数据目录

根目录的 `.env.example` 可以复制为 `.env`，按部署环境调整。管理端和读者端必须使用相同的 `DSDOCS_DATA_DIR`；默认内容目录为用户目录下的 `.local/share/dsdocs`，账号位于其中的 `accounts` 子目录。

```bash
DSDOCS_DATA_DIR=/absolute/path/to/dsdocs-data
DSDOCS_URL=http://127.0.0.1:5182
```

示例中的路径需要替换为自己的绝对路径。`DSDOCS_URL` 应与浏览器实际使用的管理入口 origin 一致，包括协议、域名和端口。

:::caution
数据库、附件和账号数据都属于运行数据，不应提交到源码仓库。实际部署口令和会话密钥也不要写入仓库或公开备份。
:::

## 容器与子路径

项目提供 `reader` 和 `management` 两个镜像目标。检查端口和配置后，可在项目根目录运行：

```bash
docker compose up --build
```

容器示例的管理入口为本机 5182，读者入口为本机 3300，读者路径是 `/docs`。管理端可写内容卷，读者只读挂载同一个卷。正式入口应通过 HTTPS 代理提供访问；仓库的 `deploy/Caddyfile` 给出了读者子路径示例。

当前管理端使用独立入口，不是 `/docs/admin`。SQLite 采用单写实例和本地持久化磁盘，不直接用于多副本共享写入或 NFS 写库。

## 更新文档与升级程序

修改文档时只需要在后台保存并发布，不必运行构建。升级程序、改变前端代码或构建时配置，则需要重新安装适用依赖、检查并构建。

管理服务停止后，读者仍可读取已发布内容；数据库和附件存储也必须保持可用。这不等于导出了一份完全独立的静态站点。

## 备份与恢复

完整备份需要保存内容数据库、附件目录、账号数据库和运行密钥。采用 SQLite 一致性备份方式，并在恢复前停止管理写入，检查文件权限与附件引用。

可选 Git 备份将内容导出到项目外的已有 Git 仓库：

```bash
DSDOCS_GIT_BACKUP_DIR=/absolute/path/to/backup-repository pnpm backup:git
```

该命令使用现有 Git 身份和签名密钥提交导出结果，默认不推送。需要推送时显式设置 `DSDOCS_GIT_PUSH=1`。定时执行可交给部署环境已有的调度机制。

:::info
Git 导出包含目录、草稿、发布快照和附件元数据，不包含附件二进制、账号与密钥，不能代替完整备份。草稿也可能含有未公开内容，备份仓库需要合适的访问权限。
:::

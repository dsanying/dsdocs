# 维护手册

开始修改前阅读 [架构](../ARCHITECTURE.md)，按任务读取 [前端规范](规范/前端.md) 和 [后端规范](规范/后端.md)。功能边界见 [能力与验收](设计/能力与验收.md)，语法范围见 [MDX 兼容矩阵](设计/MDX兼容矩阵.md)。

Node.js 使用 26，pnpm 使用 12.8.1，各应用依赖精确锁定。安装使用 `pnpm install:all`。应用配置通过进程环境传入；仓库中的 `.env.example` 仅为示例，不会自动加载。

## 验证入口

| 命令                        | 范围                                                            |
| --------------------------- | --------------------------------------------------------------- |
| `pnpm -C apps/admin check`  | 管理端类型、ESLint、内容表单测试和生产构建                      |
| `pnpm -C apps/site check`   | 内容服务类型、数据与安全测试、生产构建                          |
| `pnpm -C apps/reader check` | 文件内容源生成、类型和静态构建                                  |
| `pnpm check`                | 前述检查串行执行，并运行实际管理流程和静态读者端浏览器验证      |
| `pnpm test:integration`     | 临时数据库和独立端口上的真实管理流程，Chromium 与 Firefox       |
| `pnpm test:chrome`          | 本机 Google Chrome 的完整界面流程、请求清单及搜索集合和可见耗时 |
| `pnpm test:reader`          | 纯静态文件服务上的读者流程，检查没有后台 API 请求               |

Chrome 验收使用独立浏览器配置和临时数据库，默认端口 14220；本机需安装 Google Chrome。使用 `DSDOCS_ARTIFACTS` 将报告与截图保存到仓库外。默认显示浏览器，持续集成可设置 `DSDOCS_HEADLESS=1`。所有业务写入通过界面操作；没有界面入口的接口和无法从正常界面触发的分支须另测，并在报告中分别列出。

浏览器依赖通过 `pnpm -C apps/admin exec playwright install chromium firefox` 安装。CI 执行类型、静态检查、测试及构建，浏览器验收在本地执行。测试结果必须对应当前源码和构建产物，不能复用改动前的通过数字。

集成测试默认使用 3210 端口，可通过 `DSDOCS_TEST_PORT` 指定空闲端口；数据库和会话均临时生成并清理。`DSDOCS_ARTIFACTS` 指定仓库外截图目录。不得停止其他项目进程或与另一个测试共用会清空的结果目录。

## 开发和交付

后台界面使用 `pnpm dev:admin`；内容服务使用 `pnpm dev`。单独使用管理端开发服务器时，将内容服务的 `DSDOCS_ORIGIN` 设置为浏览器使用的开发 origin `http://localhost:5174`，API 与预览由 Vite 代理。

交付前执行完整验证入口，只暂存本次文件。维护者提交使用 dsanying 身份及 `git commit -S` 现有签名密钥，禁止用 API 创建提交或关闭签名。生产部署通过相应环境的声明式配置，不直接修改 GitOps 管理的资源。

详细审核证据、浏览器截图、临时凭据与原始日志放在仓库之外。仓库只保留可复用规范、测试和简洁的功能状态说明。

# 维护手册

开始修改前完整阅读 [架构](../ARCHITECTURE.md)，按任务阅读 [前端规范](规范/前端.md)、[服务规范](规范/后端.md)、[能力与验收](设计/能力与验收.md) 和 [MDX 兼容矩阵](设计/MDX兼容矩阵.md)。

Node.js 使用 26，pnpm 使用 12.8.1。各应用依赖精确锁定；安装使用 `pnpm install:all`。Studio 通过官方配置运行，配置中不得放置口令。唯一品牌展示名为 DSdocs，技术标识为 dsdocs。

## 验证

| 命令                   | 范围                                                                    |
| ---------------------- | ----------------------------------------------------------------------- |
| `pnpm check`           | 附件复制测试、Studio 配置类型、读者端类型、静态构建及许可收集           |
| `pnpm test:reader`     | 纯静态服务上的原生组件、搜索、语言、移动布局，无后台请求                |
| `pnpm test:deployment` | 构建本地镜像、实际认证与 WebSocket 拒绝路径、编辑端停止后的独立读者服务 |
| `pnpm test:studio`     | 安装的 Google Chrome 中验证官方 Studio 文件操作与保存                   |

浏览器使用独立配置，禁止复用日常账号。浏览器工具包位于 `apps/studio`；需要 Firefox 时使用 `pnpm -C apps/studio exec playwright install firefox`。测试附件、截图和报告放仓库外，通过 `DSDOCS_ARTIFACTS` 指定目录。不能用旧实现的覆盖率作为新架构的验收证据。

`pnpm studio` 默认本机 5180，`pnpm dev` 是读者端开发服务器 3300，`pnpm preview` 是构建产物预览 3200。不得停止其他项目进程。静态预览不是生产服务器。

## 提交与发布

完成适用检查和构建，只暂存本次文件，以 `<type>(<scope>): <中文简述>` 提交并推送当前分支。维护者提交须用 dsanying 身份和 `git commit -S`，不能用 API 创建提交或关闭签名。

生产资源由环境声明管理，不直接修改 GitOps 线上对象。当前允许本地构建与验证，不包含实际标签、Release、镜像上传或集群部署。

# 维护手册

先读 [架构](../ARCHITECTURE.md)，再按任务阅读 [前端规范](规范/前端.md)、[后端规范](规范/后端.md)、[Markdown 契约](设计/Markdown契约.md)、[API 契约](设计/API契约.md) 及 [能力验收](设计/能力与验收.md)。

展示品牌 DSdocs，技术标识 dsdocs。Node.js 26、pnpm 12.8.1，依赖精确锁定。安装执行 `pnpm install:all`。管理端直接组合公开组件，读者端保留 Fumadocs 原生机制。不得修改 node_modules 或全局技能包。

## 本地运行

`pnpm manage` 在 5182 提供生产管理服务，需先 `pnpm build`；`pnpm dev` 在 3300 启动读者开发服务；`pnpm preview` 在 3200 启动读者生产服务。两个服务必须使用相同 DSDOCS_DATA_DIR。默认数据目录为用户目录的 `.local/share/dsdocs`，账号默认独立存放该目录下的 `accounts` 子目录；可以设置 DSDOCS_AUTH_DATA_DIR。

初始教程与载入规则见 [初始内容](设计/初始内容.md)。新库默认载入教程；已有数据库不自动补齐，可用 `DSDOCS_STARTER=none` 关闭或在空站点执行 `pnpm content:init`。

首次自动创建 admin/admin，必须修改两者才能进入后台。不在源码、镜像或明文配置中保存实际部署口令。运行时密钥和数据不得进入仓库。测试使用临时数据库及独立浏览器上下文，截图不包含密码输入或 Cookie。

## 质量门禁

`quality/manifest.json` 为项目质量命令注册表，`pnpm check` 运行规范与工程边界、管理端完整门禁、服务测试、读者端检查及构建。管理端细分规则、命令与用例由 `docs/规范/manifest.json` 登记。CI 执行静态检查与构建；浏览器验收只在本地执行。`pnpm test:system` 执行隔离服务 API 回归；`pnpm test:browser` 在 Chrome 操作后台并验证读者，默认同时运行 Firefox 读者。`pnpm audit:all` 检查依赖公告。

浏览器证据经 DSDOCS_ARTIFACTS 写到仓库外。失败、未执行和通过分别登记到 [验收记录](设计/验收记录.md)。不复用旧 Studio 或 authentik 结果，不用跳过、降低阈值或放宽白名单掩盖回归。

# 验收记录

日期：2026-10-16。本记录仅对应数据库版本的 DSdocs，不沿用旧 Studio、Payload 或 authentik 的测试结论。未创建 Release、标签，未上传镜像或部署集群。

## 实现范围

管理端为 React、Ant Design 与 MDXEditor，读者端保留 Fumadocs UI/Core 的布局、目录、搜索弹窗、主题及正文组件。DSdocs 自己负责内容模型、目录、发布、附件、翻译关联和账号管理。没有修改上游包源码；管理共享组件所需的锁定补丁随仓库分发。

正文为 Markdown/GFM，支持五种标准提示框、有序列表、表格、图片、附件与代码。可视化和源码共用一个草稿。首版不执行 MDX、HTML、JavaScript 或任意 React 组件，也没有标签页、AI 或多人协作功能。

草稿自动保存；点击发布后替换已发布快照，读者无需构建。可见的读者页每 5 秒检查发布指纹，切回窗口时立即检查。管理与读者是独立进程，读者直接只读访问数据库；管理停止后继续服务，仍然依赖数据库和附件存储。

## 覆盖率与边界

`pnpm test:coverage` 对管理服务器和共享内容层测得：行 89.24%、分支 76.99%、函数 91.04%。不包含浏览器端、Next.js 内部或第三方依赖代码。没有宣称前端操作覆盖每个接口的每条分支或每一行代码；可选 Vite 开发代理/WebSocket、部分异常 I/O 等尚未完整覆盖。

本轮验证本机 Chrome、Firefox 读者和本地 Linux 容器。未验证生产 HTTPS、集群入口、真实多人并发压力、大规模搜索、完整备份恢复演练或其他浏览器的全面兼容性。SQLite 限单写实例和本地磁盘，不支持直接多副本共享写库；当前没有通用升级迁移引擎。

Git 功能是可选 CLI 内容导出与签名提交，可交给外部调度；不是内置持续同步服务。导出含目录、草稿、发布快照及附件元数据，不含附件二进制、账号和密钥。历史版本中的附件引用不阻止删除，恢复后发布会重新检查附件存在性。管理端当前使用独立入口，不声称支持 `/docs/admin`。

## 本轮修复后复验

复核时发现中文或表情跨 HTTP 数据块时可能被分别解码破坏，已改为收集字节后统一解码，并增加分块回归。首次设置表单的用户名正则也按浏览器原生约束修正。依赖更新造成的类型冲突通过锁定一致版本解决，没有屏蔽类型检查。

最后一轮曾因将原生 `--env-file-if-exists` 参数带入 Next.js 子进程而构建失败，已改为由 Next 配置加载根目录环境文件；这次失败不计为通过，修改后重新执行门禁、浏览器和容器检查。目录与附件读取失败也补上了就地重试入口。

发布与其他内容写操作共用串行队列，避免读取待校验草稿后被其他写请求替换，以及附件删除检查与发布之间的交错。新增 HTTP 分块交错测试在修复前实际得到不应出现的发布成功（200），修复后返回版本冲突（409），保存后的非法正文另行发布返回 422；测试在临时数据库执行，未接触真实内容。

截图复核发现编辑操作组误用了共享 Stack 的默认纵向布局，已切换为横向可换行操作组，并增加发布按钮宽度检查。最终截图在抽屉关闭后、正文进入可视化模式时记录，避免以过渡动画截图作为验收结果。

全新 GitHub runner 曾在许可证生成阶段因输出目录不存在而失败，已由收集器递归创建输出目录，增加全新临时嵌套目录的生成回归；本地移走已有 public 目录后重新执行门禁。该 CI 失败独立保留，不计为通过。

## 管理端分区布局（2026-10-17）

以共享 ViewportFrame/SidebarFrame 固定视口高度和侧栏上下区，中部主导航、文档目录、文档正文及普通页面各自拥有滚动边界。正常桌面视口保留文档标题、操作及元数据；窄屏和短视口只在当前编辑工作区内部滚动，不裁掉需要访问的内容。读者端滚动机制未改动。

本轮十三道工程门禁通过；Chrome 与 Firefox 的亮暗主题均实际验证账号区锚定、35 篇长目录、长正文滚轮往返、到边界继续滚动、400px 短视口和 320px 窄屏，四组组合通过，页面和控制台诊断为空。既有十六组编辑、发布、附件、账号和读者回归通过；六组设置与文件同步、四组初始教程流程复验通过。

初轮夹具因用户名选择、异步图片尺寸变化及浏览器对大滚轮增量的处理而失败，按实际加载和滚动行为修正验证。固定工作区关闭浏览器滚动锚定补偿，避免编辑器/布局变化触发 Firefox 的锚定警告；未过滤该警告。技能共享包另新增十四项几何正反例，实际项目源码保持独立，不依赖跨仓库路径。

首次远程 CI 的几何及功能断言通过，但 Linux Firefox 仍报告页面根锚定补偿告警，整轮失败不计为通过。补充仅在具有视口壳时禁用 html/body 的自动锚定，并在浏览器中断言实际计算样式，保留零控制台诊断要求。

第二轮远程 CI 表明仅设置根页面仍不足以禁用嵌套滚动容器的锚定。进一步在共享 ScrollRegion、侧栏底区和管理工作区显式关闭自动锚定，并逐一检查主导航、目录和正文滚动区的计算样式；继续保留功能、几何与控制台三类断言。

## 管理端移动布局（2026-10-17）

此前的窄屏门禁只验证页面根不溢出和当前编辑区可滚，未识别常驻文档列表占据高度、操作栏状态竖排及工具按钮挤成几像素的问题。管理端现以 Ant Design 的 lg 断点切换：小于 992px 使用顶部导航入口与原生 Drawer，目录按需打开，文档信息默认收起，次要操作放入原生 Popover。桌面仍保留分栏。编辑器挂载与草稿生命周期不因断点或面板开关改变，工具栏通过公开 toolbarClassName 入口保留控件宽度。

浏览器门禁增加 320/390/768/990px、992/1024px 桌面边界及 844×390 横屏，检查抽屉导航、列表选择后关闭、底部账号、信息展开、次要操作与历史入口、工具按钮实际宽度、元数据与源码保存往返，以及触摸模式登录和文档选择。截图在抽屉遮罩退场后保存，避免过渡帧误作最终布局证据。

验证过程保留了真实失败：原生中文按钮自动插入间隔导致新用例名称不匹配，按实际可访问名称修正；一次 Firefox 运行报告异步滚动性能提示，保留零诊断断言并添加阶段日志，后续结果另行记录。没有将该提示加入忽略清单。本轮不修改全局技能包。

阶段日志将 Firefox 提示定位到 390px 源码往返，源码编辑改用 CodeMirror 自身滚动区与公开样式类约束高度。编辑器因此正常启用虚拟化，不能再把可见 DOM 文本视为全文；新增用例改为真实键盘移动至文末、插入标记、切换后再次移至文末核对并删除标记，避免读取可见部分再覆盖整篇测试文档。

本轮最终本地结果：十三道工程门禁通过；Chrome/Firefox 亮暗主题四组布局与保存流程、两组触摸流程全部通过，应用诊断为空，报告保留一条已核实的 Firefox/CodeMirror 上游提示。此前既有十六组编辑发布、附件、账号与读者回归通过。证据位于仓库外 dsdocs-mobile-20261017/verified，未复用用户账号或改动现有数据库。

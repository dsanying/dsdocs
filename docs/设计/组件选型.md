# 组件选型与模块边界

DSdocs 优先使用已有产品的公开接口和配置。下表明确区分 Fumadocs 官方组件、官方支持的运行方式，以及 DSdocs 自行选择的第三方服务；“适合本项目”不等于“Fumadocs 官方推荐”。

| 板块                           | 组件                                         | 选型依据                                                                     | 独立能力                                             |
| ------------------------------ | -------------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------- |
| 读者布局、目录、主题、语言菜单 | fumadocs-ui、fumadocs-core                   | Fumadocs 官方包，保留原生界面                                                | 不依赖 Studio、账号或数据库                          |
| 内容源和编译                   | fumadocs-mdx                                 | 官方文件内容源，MDX 文件为唯一来源                                           | 可在其他官方支持的 Fumadocs 项目中使用文件           |
| 运行与静态构建                 | Next.js                                      | Fumadocs 官方支持的框架，本项目选择静态输出                                  | 构建后不需要 Node.js 服务                            |
| 可视化编辑、文件树与同步       | 官方 Studio；统一面板组合官方 Editor UI/Core | 官方包及公开 API，未修改上游代码；统一面板是 DSdocs 的薄集成                 | 原版 Studio 仍可直接运行；统一面板不强制账号         |
| 搜索                           | 官方 FlexSearch 静态客户端与搜索组件         | 采用已有官方适配，不开发搜索 API                                             | 索引随静态站点发布                                   |
| 数学公式                       | remark-math、rehype-katex                    | 按 Fumadocs 官方数学配置接入                                                 | 构建插件，不依赖账号                                 |
| HTTP、静态服务、反向代理       | Caddy                                        | DSdocs 选择的成熟第三方服务；authentik 提供官方 Caddy 接入配置               | 可替换为实现同等边界的已有入口                       |
| 可选账号、用户组与登录页面     | authentik 开源版                             | DSdocs 选择；满足原生网页账号管理与组准入，使用官方 Proxy Provider/Blueprint | 不进入 reader、Studio 的包依赖，可省略或复用现有实例 |
| 可选账号持久化                 | PostgreSQL                                   | authentik 官方部署依赖                                                       | 只存身份数据，不存 DSdocs 文档                       |
| 历史与发布                     | Git 与现有 CI/CD                             | 复用通用工具，不开发另一套发布后台                                           | 与账号服务独立                                       |

## 可以组合的方式

| 方式                           | 所需部分                                     | 适用场景                                                                          |
| ------------------------------ | -------------------------------------------- | --------------------------------------------------------------------------------- |
| 只用读者端                     | apps/reader                                  | 自己维护文件，直接构建 /docs                                                      |
| 读者端加编辑端，不使用账号体系 | reader + Studio                              | 单机、SSH 转发或其他可信私有入口                                                  |
| 简单密码入口                   | reader + Studio + Caddy Basic Authentication | 少量固定维护者，无网页账号管理需求                                                |
| 完整账号管理                   | reader + management + Caddy + authentik      | 统一面板创建、启停和重置密码；原生后台提供删除等运维操作                          |
| 复用既有身份服务               | reader + Studio + 入口代理                   | 现有 authentik 可直接配置；其他身份服务按其官方代理接入方式适配，不声称零配置通用 |

账号组只控制是否允许进入编辑服务，组内不再细分文档权限。DSdocs 编辑者不自动成为身份服务超级用户；统一面板仅能管理 dsdocs 路径本地账号，系统身份操作由 authentik 管理员执行。

## DSdocs 自己维护的内容

自行维护统一导航、必要账号表单、服务端 API v3 薄适配，以及语言偏好、静态子路径和图片地址适配、附件构建复制、启动命令、部署配置与测试。它们不是另一个内容模型、编辑器、账号系统或授权引擎。

不使用身份模块时，不加载其 Compose 文件，无需设置其环境变量，不启动 PostgreSQL。读者端和 Studio 均不导入 authentik 客户端 SDK。身份服务故障会阻止新的后台准入，但不会阻断公开读者端。

## 版本与兼容

Fumadocs 与 Studio 按应用锁文件安装；authentik 固定 2026.8.4，依据同版本官方 Compose 和 Proxy Provider。PostgreSQL 采用官方 Compose 的 16 系列并固定镜像摘要。升级先在隔离环境验证配置、蓝图、登录、用户组、已连接会话、上传与静态构建，再更新版本，不跟随浮动 latest。

账号服务自带简体中文，默认品牌设置 zh-Hans；文档编辑器按用户确认保留官方英文控件。

统一面板使用官方组件并不意味着官方提供了账号或项目管理产品。API v3、组件 props 与公开主题是集成边界；固定锁文件和回归测试降低升级成本，但不承诺上游破坏性升级无需适配。

Studio 仍处实验阶段，不能承诺全部 MDX 可视化；独立入口与 /docs 子路径限制保持不变。认证入口的会话和 WebSocket 失效时间必须实际测量，不把配置值当作已证明的撤权上限。

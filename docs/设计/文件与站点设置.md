# 文件与站点设置

数据库保存运行状态、草稿、发布快照及版本。管理服务在数据目录下维护 `workspace` 文件工作区：面板保存写回文件，直接修改文件也会导入相同的数据模型。两个入口均可使用，不需要重新构建。

## 网站设置

后台「网站设置」分基本信息、阅读外观、导航与语言三组。站点名称、简介、标识、浏览器图标、字号、字体、行高、品牌色、默认主题、宽度、目录、面包屑、前后篇、搜索、初始语言、首页及页脚均可修改。恢复默认值先改变表单，点击保存才生效；取消不发请求。部署端口、数据库位置和密钥不是网站设置，不允许通过表单改写。运行信息仅展示 Node.js、存储类型和文件工作区位置。

同一设置也可在 `workspace/site.json` 修改，字段与后台一致，格式由服务器校验。设置即时生效；已打开的可见读者页沿用五秒刷新检查。默认语言用于首次进入 `/docs`，手动语言偏好优先；主题同样优先保留读者主动选择。字体使用本机字体栈，不加载远程字体。

设置仅允许已登记字段，不接受脚本、任意 CSS 或任意环境变量。图片必须为已上传附件；设置中的图片可公开读取，删除前须先解除引用。非敏感设置随可选 Git 导出备份，账号和密钥不导出。

## Markdown 与目录文件

`workspace/documents/<id>.md` 保存文档，开头为 JSON 对象格式的 front matter，后面是受限 Markdown：

```markdown
---
{
  "title": "入门",
  "slug": "getting-started",
  "locale": "zh",
  "description": "从这里开始",
  "folder": null
}
---
## 第一节

这里是正文。
```

新建文件可以省略 `id` 和 `translationId`，首次导入会补齐。已有文件须保留这两个标识和语言；翻译关联与正文语法采用现有契约。这里支持的是 JSON front matter，不是通用 YAML 解析。文件名可改，但必须是目录内的普通 `.md` 文件；不支持子目录和符号链接。目录层级由 `folder` 和目录 JSON 的 `parent` 表达。

目录保存为 `workspace/folders/<id>.json`，字段是 `id`、`title`、`titleEn` 和 `parent`。新建目录省略 id 即可。文档文件变化进入草稿，不自动发布；面板可视化编辑和源码编辑修改同一份正文。格式错误的草稿允许保留，发布时仍须通过 Markdown 与附件校验。

面板保存后写回文件；管理服务约每 1.5 秒检查文件，并在内容请求前再次检查。管理服务关闭时可以编辑文件，重启管理服务后导入。读者独立读取数据库快照，不会自行扫描文件或把未发布内容暴露出来。

删除文件不会删除数据库内容，缺失文件会恢复，避免挂载或编辑器异常导致误删。正式删除可在面板执行，或在已有文件元数据中明确写入 `"deleted": true`；非空目录仍不能删除。不要直接改 SQLite 或 file_state 表。

## 冲突与备份

后台「文件同步」显示路径和异常，可比较文件与面板版本，并明确选择采用哪边。解决请求校验文件指纹和面板版本，比较后又发生修改时拒绝覆盖。格式错误或重复 ID 会阻止相应条目的面板写入；修复文件后重新检查即可。版本冲突的表单不会被自动清空。

被替换的文件及导入前的面板正文写入工作区 `.history`，不包含账号。该目录需要纳入运营备份和容量管理，不替代完整的数据库与附件备份。文件比较和临时文件重命名可降低冲突风险，但普通外部编辑器不参与数据库事务，不承诺跨数据库、文件系统的原子提交；避免多人同时改同一文件。写入后若同步失败，保留数据库草稿和磁盘文件，并显示冲突，不回报同步成功。

单写管理进程负责导入与导出；不支持多实例共享写入。所有管理接口沿用登录、首次设置、同源检查；文件系统写权限等同于本地管理权限，应限制数据目录的访问。运行文件不进入源码仓库。

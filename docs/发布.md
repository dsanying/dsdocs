# 发布

当前只准备发布流程，不创建正式版本、标签、GitHub Release 或上传镜像。

建议以签名 Git 标签标记版本，在 GitHub Release 中附源码与校验和。构建好的静态站点是具体内容制品，按站点部署，不必放进框架 Release。需要容器时可分别构建 Dockerfile 的 reader 与 studio 目标，通过现有 CI 推送镜像仓库。

发布前执行 `pnpm install:all`、`pnpm check`、`pnpm test:reader`、`pnpm test:studio`，验证容器配置与认证入口。生成依赖许可清单，检查归档不含 node_modules、构建缓存、凭据和个人文档。只将验证通过的新产物替换到服务中。

上游 Studio 仍处于实验阶段。发布说明必须列明已验证的上游版本、MDX 支持集合、Studio 独立入口和保存/发布分离，不沿用旧数据库后台的能力声明。

# 部署

读者默认位于 `/docs`，管理端默认本机 5182。两个独立 Node 服务共享内容目录；管理端可写，读者只读。使用 Node.js 26 和 pnpm 12.9.0，先冻结安装和构建，再运行。

```sh
pnpm install:all
pnpm build
pnpm manage
```

另一个终端执行 `pnpm preview`，访问 `http://127.0.0.1:3200/docs`。管理端访问 `http://127.0.0.1:5182`，首次凭据 admin/admin，登录后必须修改默认用户名和密码。数据默认保存在用户目录 `.local/share/dsdocs`，不在源码目录。

容器示例为 `docker compose -f deploy/compose.yaml up --build`，此命令会实际创建服务和持久卷；运行前检查端口及 DSDOCS_MANAGEMENT_URL。镜像以 node 用户运行，命名卷初始目录由镜像预设权限。SQLite 不应在 NFS 多写实例运行。

生产通过 HTTPS 代理暴露读者和管理服务，管理 DSDOCS_URL 必须与用户实际访问的完整 origin 一致。不得将开发 Vite 入口公开。`deploy/Caddyfile` 提供读者域名子路径示例；管理端使用独立域名，不声称当前管理 UI 已支持任意子路径。

读者没有管理服务健康依赖：管理停止后，已有内容继续可读；存储不可用时不会自动生成另一份独立站点。备份需要内容库、附件及账号库；Git 内容导出不能代替完整恢复备份。

## 可选 Git 备份

设置 DSDOCS_GIT_BACKUP_DIR 为项目外的已有 Git 仓库根目录，执行 `pnpm backup:git`。该命令导出目录、草稿、发布快照及附件元数据到 dsdocs-backup/content.json，使用已有 Git 身份与签名密钥创建签名提交。仅在显式设置 DSDOCS_GIT_PUSH=1 时推送。可由部署方已有调度机制定时执行，不阻塞文档发布。

Git 导出不包含账号、密码、会话、密钥和附件二进制，不是完整灾难恢复备份。含草稿的备份仓库应保持适当访问权限。完整备份采用 SQLite 一致性备份及附件目录备份，恢复前停管理写入并核对引用。

根目录 `.env.example` 可复制为 `.env` 配置本地管理与读者服务。环境变量优先于该文件；不要将实际数据目录、账号库或密钥提交到仓库。Compose 同样读取根目录环境配置。当前默认提供 `/docs` 读者子路径和独立管理入口。

## 初始教程

全新内容数据库首次启动管理端时自动载入四个主题的中英文教程、Markdown 格式示例及本地示例附件。首次启动前设置 `DSDOCS_STARTER=none` 可以从空站点开始；已有数据库和已删除的示例不会自动恢复。已有空站点可以运行 `pnpm content:init`，存在任何文档、目录或附件时命令会拒绝覆盖。详见 [初始内容](设计/初始内容.md)。

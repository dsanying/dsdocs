# 部署

## 静态读者端

执行 `pnpm check`，将 `apps/reader/out` 挂载在域名 `/docs`。配置静态服务器保留目录索引和真实 404，不把所有路径回退为首页。其他子路径在构建前设置 `DSDOCS_BASE_PATH`，同时修改服务器挂载路径。

静态文件可直接部署到现有集群，不需要编辑进程。更新采用新制品替换，构建失败时保留旧版本。

## 私有编辑入口

本地运行 `pnpm studio` 即可；默认只绑定回环地址。远程使用可通过 SSH 端口转发访问，避免公开 Vite 服务。

Compose 提供 Caddy 认证示例。先交互生成 bcrypt 哈希：

```sh
docker run --rm -it caddy:2.11.7 caddy hash-password
```

将用户名和哈希经进程环境传入 `DSDOCS_EDITOR_USER` 与 `DSDOCS_EDITOR_PASSWORD_HASH`；不得将口令写进源码、配置、命令历史或提交到 Git。再运行：

```sh
docker compose up --build -d
```

`http://127.0.0.1:3200/docs` 为读者端；`http://127.0.0.1:5180` 为认证保护的官方 Studio。容器内部编辑端不映射宿主端口，外部请求必须经过 Caddy。对外开放时需在受控入口配置 HTTPS，不能将明文 HTTP Basic Authentication 用于公网。

官方 Studio 使用根路径协议端点，因此独立编辑入口不能替换成只代理 `/docs/admin`。不要把这些根路径转发到业务域名并声称满足纯子路径部署。

编辑会更新宿主机 `apps/reader/content/docs`。容器用户为 node，宿主目录需允许该用户写入；不要以放宽为全员可写的方式处理权限。读者镜像在构建时固定内容，保存后执行 `docker compose build reader` 和 `docker compose up -d --no-deps reader` 才会更新读者端。

单独停止 Studio 不影响静态读者内容。此示例不自动提交 Git、备份或发布；使用现有 Git 与 CI/CD 流程管理这些步骤。

# 前端规范

## 适用范围

管理端采用 React + Ant Design，使用个人前端体系的共享源码、token、主题和反馈机制。专业编辑入口 MDXEditor 和读者端 Fumadocs 属于原生兼容入口，保持公开 API、编辑模型和生命周期；不强行套用 Ant 控件，也不修改第三方包。项目规范由本仓库独立维护，不依赖全局技能目录。

管理端普通布局使用共享 PageStack/Stack，目录使用 SidebarMenu，账号操作使用 AccountMenu，实体表单使用 DrawerForm，表格使用共享 Table。数字左对齐，默认每页 10 条，完整集合排序后分页。字段解释用 Form.Item tooltip；不以 placeholder 代替标题。操作失败保留用户输入，读取失败就地显示并提供重试；写操作结果只经共享 feedback 在右上角显示。

正文格式参见 [Markdown 契约](../设计/Markdown契约.md)。可视化与源码模式共用同一个草稿，源码错误不能清空原文或覆盖已发布版本。自动保存不弹操作通知，状态在文档页显示。编辑预览和读者的组件语义一致，具体外壳分别由编辑器和 Fumadocs 管理。

## 分区布局

管理壳使用 ViewportFrame 约束视口，SidebarFrame 将品牌、中部导航和底部账号与主题分区。导航内容增减不改变底部位置。文档目录与正文分别独立滚动，标题、主要操作和元数据在正常桌面视口保持可见；窄屏和短视口允许当前编辑区内部滚动，确保所有内容可达。普通资源页和设置页由自身工作区滚动，不能撑高页面根。读者端继续使用 Fumadocs 原生阅读滚动。

`pnpm test:layout:browser` 在隔离账号及数据中使用 Chrome 和 Firefox，验证亮暗主题、长目录、长文、短视口和窄屏下真实滚轮正反向与边界行为；检查页面根不滚动、底部控件位置及区块互不干扰。

## 交付门禁

执行管理端 TypeScript 与生产构建、读者端 TypeScript 与生产构建。真实浏览器验证目录、编辑、保存、发布、附件、账号、搜索、语言与移动布局。记录控制台错误，失败路径检查可见错误与输入保留。不得用源码快照代替功能验证，不能声明逐行或 100% 覆盖而没有覆盖率证据。

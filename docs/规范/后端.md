# 后端规范

## HTTP 与输入

所有内容和账号管理接口先鉴权，再检查首次设置和角色。写操作校验 Origin、Content-Type、字段允许清单及大小；SQL 使用参数绑定。错误响应不得包含栈、密码、会话和磁盘路径。账号接口不接受客户端提交角色或用户组。身份失效不降级匿名访问。

本地账号默认 admin/admin 仅用于初始化。首次必须更改默认用户名及密码，完成前不能编辑、上传或管理账号。超级管理员不能删除或降级；管理员只能看到自己并核验当前密码后修改自己的账号。超级管理员可以新增、删除普通管理员及重置其密码；密码仅哈希保存。账号修改后撤销会话。无账号模式必须显式选择，默认仍启用认证。

## 内容与资源

草稿保存、发布、版本恢复采用版本号控制。发布必须服务器校验格式和附件存在性，不能只依赖编辑器限制。校验与提交之间不能允许异步写入改变被校验内容；附件删除引用检查与删除也须共用写入序列。读者不得返回草稿或未发布附件。附件文件名不能参与服务器路径构造；仅以随机 ID 保存。删除仍有引用的附件和非空目录返回冲突。

数据库和密钥运行时创建在数据目录，权限限制为当前服务用户；备份需一致地包含内容库和附件。生产 SQLite 使用单写实例、本地持久化盘及只读读者挂载。禁止运行时修改 GitOps 线上对象。

## 验证

使用隔离临时数据库测试首次设置、登录失败、越权、伪造 Origin、会话撤销、版本冲突、语法拒绝、附件校验和删除保护。测试只记录状态及断言，不输出凭据或 Cookie。每个新增接口必须登记在 API 契约及验收映射中。

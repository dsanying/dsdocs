# 后端规范

内容服务的 HTTP、输入模型、存储、文件导出和编译职责分离。HTTP 入口负责请求格式、来源、会话和 CSRF；输入模型严格校验未知字段；存储负责当前账号状态、事务、版本和副作用；内容层负责 MDX 安全及渲染契约。

写操作的权限检查必须覆盖事务内执行时刻。不能用页面按钮隐藏、客户端角色或事务外预检代替服务端检查。后台只有有效管理账号与无管理权限两种状态，不引入编辑者、发布者等角色差异。

持久化查询使用参数绑定。保存和发布必须校验预期版本，操作 ID 与账号及完整请求指纹绑定。成功写入和成功审计在同一个事务完成；失败不移动公开指针，不产生成功记录。处理异步编译后仍需重新检查当前账号与版本。

私有文档、历史、预览和未公开附件不能通过匿名接口、搜索、导出或错误信息泄漏。导出只包含已发布快照及其实际引用附件。公开的静态制品不受后台即时撤回控制，部署文档必须说明重建条件。

CMS 保存 MDX 原文。草稿允许语法错误并返回诊断，预览与发布必须拒绝不支持的语法、执行表达式、未知组件、非法属性和危险 URL。验证器、渲染器和编辑器支持集合有差异时必须明确说明，不可仅凭编译成功声称实际渲染可用。

密码、会话、Cookie、完整数据库异常和作者正文不得写入日志。凭据只通过运行环境提供，数据库和附件不提交到 Git。迁移必须有旧结构、正常数据和拒绝路径测试，不能通过删库实现升级。

新增接口应从 Next.js 路由方法导出追到服务函数，并经真实 HTTP 验证。直接调用 `handleApi` 的单元测试不能证明实际路由已开放相应方法。发布准备不包含真实标签、Release、镜像上传或集群部署，除非用户明确要求执行。

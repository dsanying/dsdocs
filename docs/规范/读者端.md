# 读者端

读者端使用 Fumadocs 原生 `DocsLayout`、`DocsPage`、搜索、侧栏、目录和语言菜单。管理端的 Ant Design 组件、设计 token、密度和页面壳不进入读者端。两端共同遵循信息分区明确、操作可达、长内容完整可读、语言一致及错误可恢复的原则。

## 数据与语言

只读进程只读取已发布内容及公开站点设置。管理服务停止后仍可独立访问；发布和设置更新不需要重新构建，已打开页面按可见性检查发布修订。草稿、账号接口和未公开附件不进入读者响应。

`/docs/zh/...` 与 `/docs/en/...` 在服务端输出对应的 `html lang`；不能依赖客户端挂载后纠正。初始入口按已保存的语言选择、浏览器偏好与网站设置决定目标语言；手动切换持续保存。关联文档通过 translationId 对应，避免靠标题或 slug 猜测。没有对应翻译时回到目标语言首页。

## 排版与交互

沿用 Fumadocs 原生响应式导航和可访问交互。正文、目录及搜索按阅读用途排版，不复制后台表格的单行滚动策略。正文 Markdown 由内容契约解析，不执行 HTML、JSX、import 或脚本。代码、表格和长路径在各自范围滚动；窄屏不得出现整页横向溢出。

网站名称、图标、字体、主题、正文宽度、语言和导航开关都由公开设置提供。CSS 只使用原生扩展入口与项目正文类；不修改上游包或依赖私有 DOM。

## 验证

服务测试验证只读及公开资源边界。业务浏览器测试覆盖中文与英文切换、实际搜索命中和零结果、源码往返后的正文、真实附件下载、亮暗主题、窄屏和发布自动刷新。语言回归同时验证无 JavaScript 的原始 HTML 与浏览器渲染结果。构建诊断与浏览器错误分别记录；上游诊断必须精确登记，不能屏蔽整个类别。

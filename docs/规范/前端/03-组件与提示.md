# 组件与提示

共享组件入口与统一配置、操作分级、Tooltip 的用途与宽度。规范总览与阅读顺序见 [README](README.md)。

## FRONTEND-COMPONENTS：共享组件与统一配置

- **组件配置的取值顺序（所有组件与图表通用）**：① 库自带的可选项里有合适的就选它（如 ECharts `emphasis.focus` 的枚举、Ant `size/variant/placement` 的枚举）；② 没有合适可选项就用库默认，不做任何处理；③ 只有可选项与默认都不满足明确的个性化要求时，才在**共享层**（`components/ui`、`components/ReactEcharts/chartTheme`）统一定制一次，并在规范里写明为何默认不满足。业务层永远只做①的传参，不做③；门禁对图表高亮、Ant 组件受控属性等按此顺序检查。
- 基础组件只从 `src/components/ui` 入口使用：`AppPage`、布局栈、响应式 Tabs/ViewSwitch、共享 `DrawerForm`/`ModalForm`、匹配规则收在尾部问号里的 `SearchInput`、说明问号 `HelpTip`、`QueryForm` 查询区、`DataTable` 数据表格、信息网格、加载/空/错反馈、状态与元数据标签、原子长值、元数据折叠、滚动区及表格配置。业务页不能直接取得被统一层接管的 Ant 原始实现，也不能从 `components/ui/*` 深层路径绕过公开入口；除公共 `components/ui/index.ts` 中受审的最小 allowlist 外，禁止重导出 Ant 或公共 UI，调用方必须直接从规定入口导入。门禁按真实 import binding 识别组件，别名和 namespace 不能绕过，本地同名组件不受误判。设计 token 与表格公共配置的 import binding 不得被局部变量、参数或 catch binding 遮蔽。业务层受控 Ant/公共 UI 组件必须显式列出必要 JSX 属性，禁止用 props spread 隐藏、注入或覆盖配置；共享包装器可以透传普通属性，但自身接管的关键属性必须在透传后显式给出。`ResponsiveTabs` 的所有 items 都没有 `children` 时自动强制为 `navigation-only`；动态不可判定的 items 必须用字面值显式声明模式，不得创建空面板后用负间距补偿。
- 切换控件按语义分三层外观：**横向页签（`ResponsiveTabs`）用 Ant Tabs `line` 原生形态**——通栏底线、主色下划线指示器与主色选中文字，共享层只管收缩、填充布局与等分变体，不做药丸轨道，页签与取值/视图控件由此天然分流；**视图/模式切换才用 `ViewSwitch`**：时间粒度、指标、排行类型、页签式视图、可视化/JSON 编辑模式等改变展示或编辑形态的互斥项；**持久化字段的取值单选（资源类型、运行模式、允许/拒绝、受众方式、显示模式等会提交给后端的选项）**：候选固定且数量少（约四个以内）一律用 `Radio.Group optionType="button"` 的默认描边按钮样式——取值当场可见、一次点击完成，外观与 `Select` 下拉同属"字段取值"语言；候选数量多、动态加载或需要搜索过滤时仍用 `Select`（如图节点定位）；`Radio` 圆点平铺不用于取值——全部选项常驻展示浪费版面。`buttonStyle`（solid 等变体）禁止（静态门禁强制），全站取值按钮组只有默认描边一种形态。取值按钮组是表单字段、选中值会随表单提交，永远不放在页签/视图切换的位置上——它用联排描边按钮，与 line 页签的下划线选中、`ViewSwitch` 的弱底药丸在形态上三者可辨；**布尔开关一律用 `Switch` 的默认形态**（裸开关、无内嵌文字），不得用 `checkedChildren`/`unCheckedChildren` 把启用/禁用文字塞进开关——带字长药丸与默认形态不一致，宽度还随文案漂移。ViewSwitch 是原生 `Segmented`——轨道与药丸造型全部走主题 token（`trackBg` 弱表面底、`trackPadding` 4px、`itemColor` 三级灰、`itemSelectedBg` 品牌弱底 `--ds-color-primary-surface`、`itemSelectedColor` 主色文字 `--ds-color-primary-text`，均为 CSS 变量、品牌种子热切换同步换色），共享层只管收缩、`block` 等分与选项标签滚动槽，不另加边框阴影；选项按内容收束（`width: fit-content`，仅等分变体占满整行）——禁止把空白容器拖到行尾，业务层也不得给 `ViewSwitch` 写死 `width`（写死会把末项裁掉，静态门禁拒绝）；语义色图标（允许/拒绝）保持自身颜色，中性图标随当前文字色。实现只允许通过组件 classNames 槽位与主题 token，不得用 `.ant-*` 选择器覆盖。面板内嵌区块的层级切割用弱表面底色差加圆角表达（表头、字段网格标签区、工具栏容器），不另加装饰线与阴影。
- 操作按语义分级并绑定统一样式与确认：正向主操作（新建、保存、查询、刷新）用 primary——品牌实色 + 自动可读前景（默认采用 Ant Design 蓝色，亮暗主题保持蓝底白字；分段项采用品牌弱底与主色文字，页签采用主色文字与下划线），不用灰底或描边式主按钮；中性操作（编辑、查看、复制、启用）用默认描边；危险操作（删除、重置、禁用、清空等改变或丢弃数据的动作）统一 `color="danger"` 并显式给出 `variant`（描边 `outlined`，表格行内 `text`）——Ant 6 只有 color 与 variant 同时给出时颜色才生效，带 `type` 时 color 会被忽略，静态门禁拒绝 `danger` 布尔属性、缺 variant 或与 type 混用；语义色（成功/警告/错误/信息/链接）与主色一样在 Ant 算法之后经 `createPreserveSemanticColors` 还原为 token，任何主题下都不得被派生色替代。危险操作必须二次确认，且**二次确认只有一种形式：锚在触发按钮上的共享 `Popconfirm` 气泡**（`components/ui/Popconfirm`），不用居中弹窗——`Modal.confirm/info/success/error/warning`、App 实例 `modal.*`、`Modal.useModal` 在业务层一律由静态门禁拒绝（静态 Modal 拿不到主题上下文，暗色主题下会出现白底黑字弹窗；居中弹窗也把确认从操作位置上拉走）。需要先取数据再确认的场景（删除影响检查、发布前摘要）用共享 `Popconfirm` 的 `prepare`（打开前的异步准备，返回 false 不弹出，结果由页面挂在对应行的 `description` 上）；摘要类宽内容加 `wide`（容器放宽到 `--ds-layout-dialog-width`）；页面级保存的二次确认（后端冲突需强制覆盖等）通过 `SaveBar.saveConfirm` 在保存按钮上打开同一种气泡。写操作失败/被拦下的结果反馈走 `notify*`，不弹 `Modal.error`；确需停留阅读的内容（如仅展示一次的明文 Key）用受控 `<Modal open>`（跟随主题）。**按钮几何只由 `size` 决定**：业务层不得用 `style` 改按钮的内边距、高度、字号、行高（`padding*`/`height`/`minWidth`/`fontSize`/`lineHeight`，静态门禁拒绝）——同一操作组里一个按钮 `paddingInline: 0` 就会和旁边的按钮左右错位；需要换行的长文本跳转用 `ActionLink`，需要更多空间用表格列宽解决。**所有可点击的按钮与链接统一“图标 + 文字”**：站内导航链接（表格“详情”、名称跳转）只用共享 `ActionLink`（`icon` 必填，业务层禁止直接使用 react-router `Link`，静态门禁强制）；≤640px 时**所有**按钮与 `ActionLink` 同步收成仅图标——文字视觉隐藏但仍是可访问名称（共享 `button.css` 统一处理，页面不得自行隐藏文字），不允许“有的收了有的没收”：Modal/Modal.confirm 的确定/取消图标由 App 根 `ConfigProvider.modal` 统一注入（共享 `confirmButtonProps`），Popconfirm 只用共享 `Popconfirm`（components/ui，注入同一组图标；业务层禁止直接导入 antd `Popconfirm`，静态门禁强制），业务层不得把 `okButtonProps/cancelButtonProps.icon` 置空（静态门禁强制）；运行时门禁 `expectConsistentActionButtons` 在每个页面扫描与契约夹具（Modal 页脚、Modal.confirm、Popconfirm 展开态）中检查：任何可见按钮缺图标、或窄屏下仍显示文字即失败。业务层每个 `Button` 必须显式传 `icon`，**同一动作全站同一图标、颜色随动作语义**（静态门禁按动作词表核对，`IconButton`、`ActionLink` 与 `Button` 同规——载体是链接也不换图标）：新建/添加 `PlusOutlined`、编辑/更新 `EditOutlined`、删除 `DeleteOutlined`、保存 `SaveOutlined`、取消/关闭 `CloseOutlined`、查询/搜索 `SearchOutlined`、刷新/重试 `ReloadOutlined`、重置/清空 `ClearOutlined`、导出 `DownloadOutlined`、上传 `UploadOutlined`、同步 `SyncOutlined`、启用 `CheckCircleOutlined`、禁用/下线 `StopOutlined`、发布/发送 `SendOutlined`、复制/克隆 `CopyOutlined`、查看/预览 `EyeOutlined`、跳转 `LinkOutlined`；`DeleteOutlined/StopOutlined/ClearOutlined` 是危险动作图标，只能出现在 `color="danger"`（红色）的按钮上，不得用作状态图标或查看入口，共享 `QueryForm`/`DrawerForm`/`ModalForm`/查询反馈的内置按钮已带图标；纯图标动作只能用 `IconButton`（label 提供可访问名称，名称提示由全局 `IconLabelHint` 统一承担），静态门禁强制。**并列操作只放共享 `ResponsiveActions`**：两个及以上并列的 Button/IconButton/ActionLink 必须由 `ResponsiveActions` 承载（flex 垂直居中、统一 8px 间距、窄屏整项换行；页头/卡片 extra、表格操作尾列及区域收尾动作靠右；内容内的添加条件等局部动作可用 `justify="start"`），不得用 `div`/`Space`/Fragment 加空 `span` 间隔拼排——那会让链接与按钮按基线排布而上下错位、各页间距不一，静态门禁按 JSX 兄弟检测；运行时门禁 `expectAlignedActionGroups` 校验同一行子项垂直中心线重合（≤1px）。**小操作区里的图标必须正中心对齐**：按钮、分段项（`ViewSwitch`）、标签、输入框前后缀、清除/下拉/关闭图标、分页箭头这类操作区内的 `.anticon`，垂直中心与操作区中心重合（≤1px），纯图标操作区水平也居中；共享层用 flex 居中承载图标（`ViewSwitch` 的 label 已内置），业务层不得让图标按基线排布，运行时门禁 `expectCenteredIcons` 在所有真实页面校验。**操作组顺序固定**：同一操作组（页头 `extra`、表格行内、卡片 `extra`、弹窗 footer）内中性动作（查看/编辑/启用/发布/同步）在前，危险动作（重置/禁用/下线）在后，删除永远最后，静态门禁按 JSX 兄弟/数组顺序强制；图标 svg 不参与容器收缩（`global.css` 排除 `.anticon`），避免窄列中图标被压没造成“有的有图标有的没有”。二次确认标题统一引用 `common.confirm.execute`（确认执行？），不带指向性长句；具体影响（如"删除后无法恢复"）放 description/content。**按钮文案一律裸动作**：新增/添加/编辑/删除/刷新/重置/保存/禁用/启用/重试等直接引用 `common.actions.*`，对象由页面标题、卡片标题、区块标题或行上下文给出，不得各页自造“刷新关联用户”“新增权限规则”这类动作+对象拼接文案；同一上下文并列多个同动作按钮必须区分对象时，用 `common.actionObjectTemplates.<action>` + `common.objects.<object>` 组合。i18n 门禁：动作上下文中中文以任一 `common.actions` 词开头且更长的文案直接拒绝。
- 可复制信息统一用共享 `CopyableValue`（表格与字段中的标识符、哈希、ID 用 `AtomicValue copyable`，其内部即 `CopyableValue`）：整块内容点击即复制，**前置**复制图标只作“此处可复制”提示而非唯一点击点，图标用 `text-tertiary` 前景色（悬停/已复制升为 `text`），不使用链接蓝；成功后图标短暂切换为对勾并以受控 Tooltip 提示“已复制”，失败经 `notifyActionFailed("copy")` 统一通知；空值占位符 `-` 不生成复制入口。非文本触发的复制（代码块按钮）用共享 `useCopyToClipboard` 取得 `copy/copied`。业务代码禁止 Typography `copyable`、自绘复制按钮或直接访问 `navigator.clipboard`，静态门禁强制；复制相关文案统一引用 `common.copy.*`。
- `StatusTag` 只表达真实状态，tone 只能是 `neutral/info/success/warning/error`；文案写状态而不是动作——启用与否统一 `common.vocab.enabled`（已启用，success）/ `common.vocab.disabled`（已禁用，neutral），不写 `common.actions.enable/disable`（静态门禁沿真实词法绑定检查组件/翻译别名和局部文案变量，拒绝 `StatusTag` 中的 `common.actions.*`，不误伤同名遮蔽），查询区的启用状态下拉同用这两个词；类型、来源、版本、语言、币种和业务标签用 `MetadataTag` 或文字。图标按钮统一用 `IconButton`，label 提供可访问名称，名称提示由全局 `IconLabelHint` 统一承担；主要操作优先显示文字。
- 操作反馈的触发条件、入口与文案见 FRONTEND-FEEDBACK；表单字段校验交给 Form 自带的字段级提示，不用通知替代。
- **并排卡片等高、不因附加信息增高**：同一行的 KPI/指标卡只由固定的三行（标签、数值、趋势）决定高度；附加信息（如“节省金额”）放进趋势行同一行而不是另起一行；货币符号与数字永远同一行（`white-space: nowrap`），宽度不够时由迷你趋势图让位（文字列 `flex: 1 0 auto`、图 `flex: 0 1`），不允许某张卡因内容多而把整行撑高留白。
- **顺序调整只有一种交互：拖动排序**，实现统一在共享层、基于 `@dnd-kit/react`（dnd-kit 新一代，`@dnd-kit/react` + `helpers` + `abstract` + `collision` 直接依赖；旧的 `@dnd-kit/core/sortable/utilities` 已移除，业务不得再引入）：表格行传共享 `Table.sortable`（首列拖动手柄、整行可拖），列表项用共享 `SortableList`（手柄起拖，`itemDisabled` 固定不可拖的项）。拖动中乐观换位、松手落位动画、键盘（空格抓起/方向键移动/空格放下）、读屏播报都由库提供，共享层只做三件事：用 `move(keys, event)` 得到新顺序并乐观渲染、松手后一次请求把该行放到目标位置再 reload（`onMove(row, fromIndex, toIndex)`）、拖动中显示顶部**取消区**（`useDroppable` + `pointerIntersection` + 最高碰撞优先级，拖入松手或 Esc 放弃、不发请求）。本地重排放在松手后的下一帧（库的落位动画要等 React 渲染完成才起播，同一任务里提交会把首帧顶后），后端请求与随之而来的 reload 必须等待官方 dragOperation 在 Feedback 清理后回到 idle；不得用默认 250ms 或其他固定计时推断动画结束。取消不写入，重复 idle 只提交一次，无动画与卸载同样清理待执行回调；单测覆盖这些状态，浏览器在 XHR 发送瞬间同步检查源行没有官方 dropping 标记，并保留完整落位生命周期的 50ms 长任务门禁；共享 `Table` 仅给没有自定义 `render` 的纯数据列默认 `shouldCellUpdate: record !== previous`；自定义渲染保留 Ant 对 render 闭包与行序号的依赖追踪，语言、搜索词与选择状态变化时同步更新，业务显式提供比较器时必须覆盖自身全部渲染依赖；拖动态用容器 `data-dragging` 切换取消区显示，不走 state。不再逐行/逐项摆“上移/下移”箭头按钮，也不用原生 `draggable`——静态门禁拒绝 `ArrowUp/DownOutlined` 作操作图标与 `draggable` 属性。操作列宽度按动作构成算：`columnWidth.actions(文字动作数, 纯图标动作数)`，纯图标动作只占 40。**数据列不锁定，操作尾列按第 04 章固定在右侧**（`columns` 里的 `fixed` 由静态门禁拒绝）：锁列在窄容器里会遮住相邻列、表头还得另补底色，放不下统一交给表格自身横向滚动。
- **下拉候选项与多选标签一律完整展开**：候选项文本与已选标签不省略、不折叠成 +N（`maxTagCount`/`maxTagTextLength` 静态门禁拒绝）。全局经 `ConfigProvider.select.classNames` 挂到 Ant 语义槽位（候选项 `popup.listItem`、标签 `itemContent`），文本过长时单行左右滚动（二者都是横向滚动槽位，见 FRONTEND-TOOLTIP）；下拉宽度按最长候选量宽、封顶查询控件宽度（`FilterSelect`）。**多选控件只有一个入口 `components/ui/MultiSelect`**：行内是正常多选——单击打开候选下拉直接搜索勾选，已选只是一行展示（标签不换行、不撑高，过长在控件内横向滚动，全局 `content` 槽位），`allowClear` 与单个标签的 `×` 移除照常行内可用；**双击控件打开以字段名为标题的批量编辑弹窗**（放在 `Form.Item` 里时自动取其关联的 `<label for>` 文本，不必再传 `label`；脱离表单时必须显式传 `label`）——弹窗是辅助输入区而不是表单：宽度固定 `--ds-layout-dialog-width`，已选区换行铺开、随内容增高到 `--ds-layout-scroll-region-max-height` 后在区内上下滚动（候选下拉紧贴已选标签下方、与输入框同宽），改动即时同步到控件值，没有确定/取消/清空按钮（清空走控件自带的 `allowClear`，关闭即完成），已选计数放在标题行。候选制下输入的文本只能是检索词，永远不会成为候选项；候选之外的已选值是红色幽灵值标签，可点标签正文弹"近似候选"气泡，选中即替换为候选真实值。**`MultiSelect` 弹窗输入区统一接受粘贴列表**：粘贴一段含空白（空格/换行/Tab）或中英文逗号、分号、顿号的文本自动切分为多个值——`freeInput` 全量收下，候选制先整串匹配（候选值本身可能含分隔符）再逐项按值或名称命中——逐项按候选真实值与名称先精确匹配，落空再做大小写折叠匹配：唯一折叠变体**自动校正为候选规范值**（已加载候选即时校正；不在已加载页里的经远端 `values`+`fold` 核验兜底，加载完成的规则值同样走这条规范化链）；核验请求本身失败按读失败处理——区域内联报错可重试，值不算作"不存在"，重试重新走核验链；多个候选只差大小写属歧义，不猜、保留为幽灵值；自动改写用户输入只在能对完整数据域证明唯一结论时发生：本地候选页、被截断的折叠结果（hasMore）都只是部分数据，不构成唯一性证明，接入远端核验时值一律先以原文入待核验集、交远端完整判定。候选是否只是一页按数据源结构判定：服务端检索（`filterOption={false}` + `onSearch`）或接入远端核验的控件都按部分候选处理，本地只认与原文精确相等的候选值，名称与折叠命中都延后远端；不依赖是否挂了提示回调；语义上是片段而非完整候选的输入（单值操作符的值）不进入修正链。完全无命中项也**不丢弃**：以原文收进已选区标红待修正。**粘贴与核验的提示按处置分流、不混报**：命中而规范值与原文不同的项（折叠变体或按名称命中）弹信息通知"已自动修正为规范候选"，逐条列出原文 → 规范值并自动关闭；仍无唯一候选的项弹"未匹配到唯一候选，已标红待修正"警告常驻——接入远端按值核验的控件先把粘贴未命中项挂起，核验（精确+折叠）落定后只对仍未决的值报警，已被自动修正或核验为真实候选的不再误报；未经远端核验接管的控件维持粘贴时立即警告。所有不在候选集中的已选标签（粘贴误入或候选后来被删）以错误色系标出且**可点击**：按近似度（同名>前缀>包含>编辑距离）列出候选，点击即替换为候选真实值，修正后红标自动消失；候选集为空或 freeInput 时不出修正弹层。该机制只属于值输入弹窗，查询区的筛选多选（`FilterSelect`）不引入。**唯一例外是查询区的筛选多选（`FilterSelect kind="enum"`）**：筛选时改动频繁，用 Ant 多选的默认形态——已选标签换行完整展示、点开即下拉勾选，不进弹窗。除这两个共享入口外，业务层与其它共享组件不得再给 Ant `Select` 传 `mode`（静态门禁拒绝）。**下拉面板宽度只随最长候选走，不跟随控件宽度**（全局 `ConfigProvider.popupMatchSelectWidth=false`，页面不再逐个声明），**但不超出视口**（`select.css` 给 `.ant-select-dropdown` 封顶 `100vw - 32px`，超长候选在自身一行内左右滚动；运行时门禁 `expectPopupsWithinViewport` 拒绝任何超出视口的下拉、气泡与提示框）——Ant 的下拉最小宽度就是控件宽度，所以行内并排的控件本身必须按内容量宽（`measureOptionsWidth`：最长候选/已选值 + 控件内边距，`max-width: 100%`），不得把候选很短的下拉铺成整行（`FilterSelect`、条件组的字段/操作符/逻辑控件都按此实现）；**控件的过渡只用于颜色/阴影反馈**：全站 Select 的 `transition-property` 限定为边框色/阴影/背景/文字色（`select.css`），宽度、外边距这类布局变化不做动画；条件组不用 react-querybuilder 的 `queryBuilder-responsive` 版式（它靠"行内边距 + 首个控件负外边距"凑位置，首个控件一变就会滑动），换行由 `.ds-filter-rules` 自己的 `flex-wrap` 表达。**候选是异步加载的自由输入控件不按候选量宽**（条件组的值控件固定 `--ds-layout-query-control-width`），否则候选到达后控件宽度会跳动；表单里独占一行的控件才铺满。
- **筛选条件组只有一个入口 `components/FilterRules`**（需要条件组语义的项目在固定路径实现这个共享组件；协议由目标后端契约决定，典型形态如 `logic` and/or + `conditions` + 嵌套 `groups`，`in/notin` 为数组、`contains` 类由后端补通配符）：编辑与只读用同一组件、同一版式——**可视化为主、JSON 为辅**，一处 `ViewSwitch` 切换，默认可视化。编辑态基于 `react-querybuilder` + 官方 antd 适配（字段、操作符与候选分别由后端筛选 schema 接口和候选接口提供，列表操作符多选、其余单选可输入，动作按钮走共享 Button/IconButton），只读态是缩进的条件树（字段 · 操作符 · 值标签，行间标出且/或，子组缩进带支线）。页面不得直引 `react-querybuilder`、不得再各自拼字段提示/模式切换/JSON 校验，也不得把条件组用 `JsonPreview` 裸展示（静态门禁强制直引；组件包装第三方库时，其 `--rqb-*` 变量只能桥接到 `--ds-*`、其类名只能出现在自己的 `.ds-` 根选择器之下）。
- **低频但必须保留的信息用共享 `SecondarySection` 收纳**（原始规则、审计明细、技术字段这类“一般没人看、但不能删”的内容）：放在页面/页签**末尾**的一条无壳折叠栏，默认折叠，只露区域名 + 一句摘要（里面有什么，用 `formatList` 连接），展开时才挂载并发起请求、收起即卸载；不为它单独建页签（页签只划分分析对象/一级视图），不删、不藏进弹窗，也不与主内容并列成同级卡片抢注意力。摘要与标题都是词项，不写说明句。
- **信息强调三级制**（密度优先，强调靠字号与位置而不是靠壳）：① 页面级英雄指标只在数据总览 KPI 卡（大数字 + 迷你趋势，每页 ≤3）；② 详情页与区块顶部“需要强调但不该各占一张卡”的少量关键数据用共享 `SummaryStrip`（关键指标条）——标签 14px（xs 档）次级色在上、数值 `--ds-font-size-metric` 加粗在下、项间 1px 竖线、不套卡片壳、一行摆多项、窄容器整项换行，语义状态用 `StatusTag` 作值、只有超额/告警类数值才用 `tone` 着色；**值是若干部分之和时用 `breakdown` 把各部分列成值下方的小字算式**（“主额度 ¥A + 附加包 ¥B”），让总数的来源一眼可见，不另开字段、不在别处重复；**“部分 / 总量”类数值只用共享 `RatioProgress`**（一行 `A / B  N%` + 与文字同宽的细进度条：宽度随内容自适应、不铺满槽位，金额与百分比同一字号、之间只留固定间隔，槽位窄到放不下时百分比整项落到下一行而金额不拆，信息网格与表格单元格同一形态，低于 10% 才用 Ant exception 红色；定期额度与剩余额度一律合成这一个组件，运行时门禁校验金额与百分比同字号且组件不越出所在槽位），不得把总量和占比拆成两个字段、也不得自绘 Progress + 文字组合；③ 成批同构键值用 `InformationFieldGrid`。业务层禁止再用 Ant `Statistic`、独立小卡片或自绘大数字块摆放“一个标签一个数字”（数据总览 KPI 卡除外）；标题 `extra` 只承载操作，不用作统计、筛选或其他内容布局区。
- Select 搜索必须区分本地过滤与服务端查询：本地使用统一匹配函数，远程使用 `filterOption={false}`、受控 loading 和防陈旧请求。只有真实语义差异才能覆盖共享默认值。
- 业务源码使用当前 Ant Design API；禁止重新引入已弃用的 `List`、`Alert.message`、`Dropdown.Button`、`Drawer.width`、`DrawerForm.width`、`Space.direction`、`Modal.destroyOnClose`、`Card.bordered`、`Tag.bordered` 等接口；同构列表统一迁移到 Table，其他接口分别使用对应的新属性。DrawerForm 的尺寸放入 `drawerProps.size`，表单正文由 Drawer body 独立滚动，提交与取消操作统一挂载到固定 footer，窄屏或长表单中必须持续可达。共享 `StatusTag`/`MetadataTag` 不暴露 `bordered`。业务层通过显式属性使用替代 API；共享包装器的透传属性必须位于接管的 `size`、`variant`、`destroyOnHidden` 等属性之前，不能覆盖统一契约。共享 `DrawerForm`/`ModalForm` 提交中禁用取消并忽略关闭、遮罩和 Esc，提交入口拒绝重复请求；完成或失败后恢复可关闭，避免旧请求关闭重新打开的表单并丢弃新草稿。真实浏览器契约覆盖这两种容器的取消、关闭与重复提交。带 `name` 的 `Form.Item` 只能绑定一个真实控件；说明、切换器和编辑器工具栏放在无 `name` 的外层项，字段值由单一受控入口登记。升级兼容问题应在统一组件或依赖层解决，不允许页面逐处压制告警。
- 下拉菜单只在有两个及以上候选时使用；只有一个动作就直接放一个写明动作的按钮（如“添加外部链接”），不拆成“按钮 + 下拉箭头”，也不用提示文字解释“当前只支持一种”。门禁检查菜单 `items` 只有一项的字面量。
- **拖动排序只用共享 `SortableList`，手柄与内容同属一块**：本身是一块内容的项（问卷题目、页面大纲、媒体）用 `variant="card"`——整项就是卡片，手柄是 `renderItem` 第三个参数给出的小组件，由项放进自己的首行（题目卡标题行、大纲行、媒体行最前），不另占一列，下面的内容照常占满卡片宽度；选中态由 `itemSelected` 给出，项里不再自己套 `Card` 或边框；一行裸控件（按钮文案、选项）用默认 `plain`。下拉候选按 `utils/collation` 的 `sortByText` 自然排序，同一组候选用等长名称（题型统一四字）。静态门禁拒绝 `renderItem` 里套 `Card`、以及 card 外观下 `renderItem` 不接手柄参数的 `SortableList`。

- 受控 Modal 由根 `ConfigProvider.modal` 注入共享 `modalDefaults`：容器高度不超过动态视口减上下安全间距，标题与页脚不收缩，仅正文纵向滚动。短视口回归检查真实弹窗与共享表单，不能只验证普通桌面高度。

原子滚动槽在弹窗和抽屉内仍可用 Tab 和方向键访问。负 `tabindex` 的普通容器只承载初始焦点，不能替代内部词项的键盘入口；只由真实启用的交互控件或非负 Tab 停靠点替代槽位入口。内容变化后重核自动停靠点，避免重复焦点。

## FRONTEND-TOOLTIP：用途、内容与宽度

Tooltip 只有四种用途，说明性操作提示与“省略后悬停看全文”都已全站移除：

**过长单项只有一种处理：单行、不省略、不折行，放不下在自身范围内左右滚动——由全局规则统一判断，不在各处自行设定**。单项指名称、标识（标识符、哈希、ID、路径）、值、译文、选项、标签、标题；句子与段落（说明、报错、帮助、对话正文）按正常排版折行，不属于“过长处理”。**唯一来源**：哪些盒子是“横向滚动槽位”只登记在 `components/ui/overflowSlots.ts` 的 `SCROLL_SLOTS`（表格正文单元格与多行格的每一行、页面标题、卡片标题、下拉候选项、弹窗里的已选标签，以及 `AtomicValue`、`LongText`、`InlineList`、通用类 `ds-single-line`）；槽位样式只写在 `overflowScroll.css`（默认 `overflow-x: hidden` + `nowrap`，标了 `data-overflowing` 才 `auto`）；运行时 `installOverflowScroll`（`main.tsx` 挂在 `body` 上，弹层同样覆盖）按同一清单测量，内容比槽位宽 1px 以上才标记、才可滚动并在无其他可聚焦元素时可键盘聚焦——放得下的槽位不截获左右拖动 / 滚轮，手势交给外层；不设 `overscroll-behavior: contain`。**槽位不带水平内边距**：滚动容器的内边距属于可滚动区域，滚动后内容会滑进内边距、贴到格子边缘，相邻两格同时滚动就连成一片；需要留白的槽位（表格单元格按 Ant 各尺寸的单元格留白）在 `overflowScroll.css` 里把水平内边距换成同宽的透明行内边框——尺寸与对齐不变、悬停底色照常铺满，滚动内容只在内容区里裁切，与邻格之间始终隔着固定留白（表格勾选列不是槽位；固定操作列保持真实 padding，不改为透明边框，避免阴影锚点与表头边界错位）。组件与页面样式只管布局，不写自己的溢出规则；新增单行展示的地方要么放进已有槽位（`AtomicValue` 等），要么加 `ds-single-line`，Ant 内部节点才在 `SCROLL_SLOTS` 加一条选择器。门禁：静态门禁校验 `SCROLL_SLOTS` 与 `overflowScroll.css` 两组规则逐条一致、其他样式文件出现 `[data-overflowing]` 规则即拒绝、`overflow-wrap: anywhere|break-word` / `word-break: break-all|break-word` 只允许出现在注明“正文折行”的规则里，并拒绝任何 `text-overflow: ellipsis`、`ellipsis` 属性与 `textOverflow: "ellipsis"`；运行时门禁 `expectNoEllipsis` 拒绝可见省略号，`expectNoStuckOverflows`（全站）拒绝“放不下却被裁切滚不动”（stuck）、“放得下却仍是滚动容器”（idle）、“槽位折行”（wrap）与“槽位带水平内边距”（padded）。Tooltip 不承担“看全文”，只用于图标操作、短帮助与复制反馈。

1. 图表数据：ECharts 自带 tooltip 展示数据点的数值，小数位受 `FRONTEND-DATA` 上限约束。
2. 结构化详情：多项键值或元数据使用 Popover/Drawer/专用详情层，可换行并有可读上限；表格单元格里的标签/短项集合不折叠、不换行，统一用 `InlineList`（见 FRONTEND-COMPONENTS）。
3. **说明性文字一律收进问号**：字段说明、格式限制、取值范围、空值含义、搜索匹配规则、图表/卡片口径说明，统一放在被说明对象旁的问号图标里，悬停、键盘聚焦或轻触时展示，不再以灰色小字常驻占用版面。表单字段用 Ant 官方的 `Form.Item tooltip`（标签旁问号）；标题、卡片等非表单位置用共享 `HelpTip`；搜索规则由 `SearchInput` 的 `hint` 渲染为输入框尾部问号并作为输入框的可访问描述。说明只能是一段纯文本，结构化内容走第 2 条。说明写给使用者看：讲清取值含义、默认值（留空时生效的值）与限制，不出现字段名、接口取值或实现细节（`api_key`、`modal`/`toast`、CSS、前后端、防抖），不复述标签（“选择上游渠道”）——没有可说明的就不加问号；同一字段的含义随其他选项变化时，说明跟着切换。**固定单位放进输入框**：秒、天、px、%、金额（`CURRENCY_SYMBOL`）用 `InputNumber` 的 `suffix`/`prefix` 常驻显示，标签不带“（秒）”，也不让人手输单位——存储格式需要带单位的（如通知宽高的 `"480px"`）由控件转换。i18n 门禁拒绝表单标签以单位括号结尾、问号说明含实现细节或只是“选择/输入 + 名词”。

4. **只剩图标时显示被隐藏的文字**：按钮 / 链接因窄屏（≤640px）或页头放不下而收成仅图标、以及本来就是纯图标的 `IconButton`，悬停或键盘聚焦时用 Tooltip 显示那段文字（就是它的可访问名称），文字完整可见时不弹。全站由挂在 App 根部的共享 `IconLabelHint` 统一负责（按 `button.ant-btn` / `a.ds-action-link` 判断文字是否被视觉隐藏，纯图标取 `aria-label`），页面不给按钮各自挂 Tooltip。 只读名称提示及其弹层不接收指针，不能阻挡下一步动作；步骤按钮改名或卸载后清理旧提示，重新悬停按当前名称显示。带交互内容的提示不套用这项只读规则。

以下内容**不得**收进问号，必须常驻可见：校验错误与请求失败（`help`）、随当前状态变化的前置条件或结果（如“先填写所属用户”“解析结果：每天 02:00”，用条件表达式写在 `extra`/`help`）、风险与不可逆影响（放在最终确认或 Alert 里，如“明文只展示一次”“删除后无法恢复”）。静态文案写成 `Form.Item extra` 由静态门禁拒绝。

不挂说明性的操作提示：按钮、图标动作、开关上不另写解释用法的 Tooltip——只剩图标时显示的就是按钮自己的文字（第 4 条），不额外加说明；复制成功等瞬时状态由组件内受控提示表达（`CopyableValue`）。业务层直接使用 `Tooltip`（除 `HelpTip`）由静态门禁拒绝；共享 `Tooltip` 不从 `@/components/ui` 对外导出。禁止固定字符切片、原生 `title`、任何 ellipsis/line-clamp 省略、手写 `<br>`、页面覆盖 Tooltip 内部样式或硬编码窄宽。

按钮的图标与文字必须位于同一个按钮表面；禁止在 Button 内只给文字另套 Tag、StatusTag、Badge 或自定义背景、边框，导致图标留在框外。状态统计的查看入口使用完整的图标文字按钮；拒绝或错误状态入口整体采用 error 语义文字、边框和弱底，图标继承同色，普通、悬停和聚焦态均保持语义。红色的只读状态入口不等于危险写操作，不因此添加确认；删除等危险写操作继续使用 danger 与 Popconfirm。真实状态标签独立展示。静态门禁保留文字单独套框的反例。

共享 DrawerForm/ModalForm 必须在表单正文挂载时恢复 initialValues，覆盖 React StrictMode 重演中 clearOnDestroy 清空表单的情形；初始化不能随普通重渲染覆盖用户草稿。保留关闭销毁和取消重开恢复原值，禁止通过关闭 StrictMode 或保留旧草稿规避。浏览器门禁同时跑生产构建和开发运行时，检查只读值、可编辑字段、排序及布尔状态回填、未修改时无保存、取消重开丢弃草稿。

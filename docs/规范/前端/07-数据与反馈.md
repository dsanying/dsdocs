# 数据与反馈

查询、图表与权威状态、通知只属于写操作。规范总览与阅读顺序见 [README](README.md)。

## FRONTEND-DATA：查询、图表与权威状态

- **局部错误只有一种样子**（共享 `QueryErrorAlert`）：一句话 + 一个重试，信息只出现一次——状态码类失败直接“<标题> (502)”，业务原因则“<标题>：<原因>”，不再标题一行、描述一行重复。**标题与重试文案统一由共享层提供**（`common.requestFailed` / `common.actions.retry`）：`errorTitle`、`retryLabel`、`onRetry` 均为可选——加载失败一律使用通用文案，页面不得为“加载/获取失败”新建专属文案键；只有语义确实不同的状态（如目标对象不存在）才可传 `errorTitle` 覆盖；无可重放的加载动作时不传 `onRetry`，重试按钮即不渲染。无可展示数据时用 `layout="block"`：与空态同一版式（居中、错误图标、一句话、小号重试按钮），占据内容区；已有旧数据、刷新失败时用 `layout="banner"`：Ant Alert 单行（图标 + 一句话 + 右侧重试 `action`）贴在内容上方，旧数据保留。`QueryFeedback`/`TableQueryBoundary`/`ChartCard`/KPI 已按有无数据自动选择，页面不得自绘错误块，也不得再手写 `Alert type="error"` 展示加载失败。
- 服务端查询区分未提交、首次加载、成功有数据、成功无数据、刷新和失败；新参数只接受末次请求结果，卸载后不写状态。失败展示真实可用错误和重试，不能伪装为空态；刷新保留最后成功内容并叠加 loading/错误反馈。`QueryFeedback`、`QueryErrorAlert` 与 `TableQueryBoundary` 的 `error` 必须显式接收可证明的原始错误标识符、错误对象的 `error` 成员或 `new Error(...)`；禁止 props spread、`.message`、字符串转换、调用包装器、拼接或模板字符串隐藏预格式化错误。共享层保留本地错误和结构化 4xx 响应中约定的业务消息；4xx 裸文本/HTML 与所有 5xx 响应正文均不可信，只显示本地标题和状态码。`DataTable` 内置共享 `TableQueryBoundary`：首次失败占据空态，已有结果刷新失败时在表格外常驻提示；使用共享 `Table` 的小型列表若有服务端请求也必须由 `TableQueryBoundary` 包裹。
- **大候选集一律实时候选，不全量加载**：主体、标识、邮箱、关联对象这类以万计的枚举只按输入关键词防抖向后端取前 N 条（`limit` ≤ 100，默认 20），已选值即使不在当前结果里也保留为选项；实现只走共享 `useRemoteOptions` 及其两个入口——查询区 `FilterSelect` 的 `loadOptions`、表单单选 `RemoteSelect`（`freeText` 允许输入候选之外的值）；给已知值补充展示字段用按值精确查询的列表描述。业务层对大候选接口的无参全量调用由静态门禁拒绝，具体接口清单登记在 `scripts/design-system.project.json` 的 `largeCandidateApis`。
- **后端原样返回，前端统一裁位**：接口不为展示做四舍五入，数值精度留在后端；展示层三道自动裁位——`DataTable` 对未自定义 `render` 的列把 number 值自动 `formatNumber`（≤3 位、去尾零、不分组，整数与 ID 原样）、`InformationFieldGrid`/`SummaryStrip` 对 number 值同样处理，自定义 `render`/拼接文本必须显式调用 `@/utils/number`；UI 测试 `expectNoLongDecimals` 在所有真实页面扫描可见文本，出现 4 位及以上小数即失败（编辑器/代码块/输入框内的原始 JSON 除外）。
- **小数位全局上限三位**：任何面向用户的数值（表格、指标条、字段网格、图表标签与 tooltip、CSV 之外的展示）最多保留三位小数；换算后仍超过三位的精确小数值（如每百万 token 的极小单价）转科学计数展示（`formatPreciseDecimal`，`0.000001` → `1e-6`），不得直接堆原始小数位，金额两到三位、百分比一位、计数为整数分组。数值格式化只经 `@/utils/number`（`formatDecimal`/`formatInteger`/`formatPercent`/`formatCurrency`/`formatCompactNumber`，内部把位数钳制到 ≤3）；业务代码禁止直接 `toFixed`/`toLocaleString`、`Statistic precision > 3`，图表禁止 `{c}`/`{d}` 字符串模板直出原始值，必须用函数 formatter；静态门禁强制。
- 独立请求并发启动，存在输入依赖的请求才串行。路由组件、主数据和次要详情分层：应用壳与 AppPage 先稳定出现，主数据随后加载，非活动 Tab/详情在首次可见或激活时加载；不能用全页阻塞等待所有次要数据。
- 独立候选字段与目录也按展示单元隔离：一个候选接口失败不能阻止其他候选字段和受众编辑，主列表不能等待仅用于标签富化的字典；标签目录与权限点目录分别加载，不能因另一个目录失败而隐藏自己的列表。字典到达后补全显示，失败在所属区域重试；有界远程候选保留已选值，不静默截断固定前 N 条作为完整集合。浏览器回归须拒绝其中一个请求并验证其余单元仍可操作，不能只验证全部成功。
- 同一报表或导出依赖多个接口时，以完整一致的查询快照作为发布边界：任一接口首次失败不生成零值或部分报表，刷新失败保留上一份完整快照并展示常驻错误；加载、失败或快照不完整时禁用导出，导出函数自身也必须拒绝不完整数据。
- 多区块主数据页面（数据总览类）采用“固定壳 + 分块并发”：页头、筛选区与各区块卡位同步渲染，每个区块由独立的请求状态（`usePageBlocks` 模式：`data/loading/error/retry`）驱动，同时发起、各自到达、各自失败并在卡片内原位重试；区块首载显示卡片内 `LoadingState`，刷新用 `LoadingOverlay` 保留旧图，不得用整页 LoadingState 或全页遮罩转圈，也不得因单个区块失败清空整页。局部条件（排行类型、趋势视图）只重取所属区块；全局条件（时间范围、统计口径）变化时清空全部区块并发重取，页面上不得混显不同条件的数据。区块级响应校验（格式、必需节点）只拒绝该区块并给出本地化错误，不泄露字段路径；后端历史差异（如空部门名）在解析层归一而不是整页失败。跨区块导出（CSV）要求全部区块按当前条件成功后才可用。单主数据详情页在内容区整页占位是允许的，次要数据仍须独立加载。
- 路由页面统一懒加载与同一 PageFallback；一切 `lazy(` 内容（页面路由、Monaco、助手内容等重组件）必须套共享 `LazyBoundary`——Suspense 只接管 pending，chunk 请求失败（部署后旧清单引用、网络断开、dev 预构建过期）会把错误冒泡到根造成整页白屏；边界把失败约束在该内容区域，按查询错误契约展示，重试即刷新页面（React.lazy 缓存拒绝结果，原地重试必失败）；携带失败或会话状态的边界一律按宿主身份隔离（key 或等价重置）——同类型同位置的复用会让上一个宿主的失败盖在当前内容上，路由边界按路由挂 key 即此原则的实例。纯声明注册表 `routes/pages.ts` 由 lazyRoute 统一带边界，属唯一豁免；共享 `useRequest` 负责普通数据的依赖稳定、末次请求胜出和卸载保护，表格请求经共享 `useDataTable`（内部委托 `useRequest`）收束分页、排序、筛选与反馈状态。局部实现不得复制不完整的请求序号或 loading/error 状态机。
- 状态保留后端权威值，前端只映射语义 tone；不得从颜色、日志顺序、数组位置或时间重叠推断权限、额度或其他业务状态。
- 报表展示维度的缺失名称由服务端统一归一化，覆盖 NULL、空字符串和纯空格；输出名称与聚合分组必须复用同一表达式，不能只补显示值而留下重复分类。前端保留响应契约校验，不通过清洗源数据或放宽校验隐藏问题；边界种子和查询回归测试覆盖这些合法缺失状态。
- **图表只声明数据与形态，外观由共享主题接管**：`components/ReactEcharts` 是唯一入口，按当前亮/暗主题用 `registerTheme` 装载 `chartTheme`（文字、8 档分类色板、提示框、图例、坐标轴与各系列类型的默认样式），业务 option 不得手写 `textStyle/fontSize/backgroundColor/borderColor/axisLine/splitLine/symbol/smooth/barMaxWidth…`（静态门禁按属性名拒绝，共享层除外）；数值格式只用 ECharts 自带 `tooltip.valueFormatter`（`chartValueFormatters.currency/integer/compact/percent/decimal`）与 `dataset` 维度名（`displayName` 即提示框字段名），坐标轴刻度用 `chartAxisFormatters`，不手写 HTML formatter；需要第二量纲轴时用共享 `secondaryValueAxis`（不画网格）。**不提供缩放/放大/拖拽/类型切换**（`dataZoom/toolbox/roam/zoom/draggable` 拒绝，不注册对应模块），范围由页面筛选决定，**全站图表画布高度统一为 `CHART_HEIGHT`（十行清单高度 = 10 × 28 + 56 = 336px）**：内容决定几何的图（正方形格热力图）标记 `data-chart-fit="content"`，画布高度随内容、不得超过 `CHART_HEIGHT`，并占满整行宽度让格子尽量大；视口随所在行高伸展的图（继承图与操作面板并排）标记 `data-chart-fit="fill"`，可见高度不低于 `CHART_HEIGHT`、等于所在行高；清单类（`BarList` / `ChartViewport`）画布按真实行数撑满，视口固定 336px、超出十行在区域内滚动；趋势/环形/热力/散点/关系图直接用 336px，同一行的图表卡片因此等高，不允许某张图把卡片撑长。运行时门禁 `expectUniformChartHeight` 校验每个 ECharts 画布的可见高度（KPI 迷你趋势图除外）；**板块利用率门禁** `expectChartUtilization` 读取各层 canvas 的非透明像素包围盒，纵向与横向占画布不足 60% 即失败——内容缩在大片空白里必须改布局（占满整行）或让画布随内容定高，不得靠留白凑统一高度。**图例按编码语义而非图形类别决定**：多系列、堆叠条形及饼图分片以颜色区分时必须有图例；共享入口为多命名系列和饼图提供默认图例，单系列且名称已由轴或标题清楚说明时可省略。分类散点每个实体作为命名系列，图例与图元使用同源分类色，不把不同模型塞进一个同色系列；热力连续数值使用色阶，关系图沿用同源 `ColorLegend`。密集标签使用内置 `labelLayout.hideOverlap`，共享入口须注册 `LabelLayout` 模块；真实画布回归核对图例取色与重叠隐藏，不能仅检查 option 存在。**所有图表类型统一版式（共享入口 `withSharedLayout` 注入，业务 option 只声明数据与形态）**：图例固定在绘图区**上方一行、居中**，条目放不下时用内置分页图例左右翻页（不换行、不放底部、不竖排）；唯一例外由共享入口自动处理：纯环形图的画布明显横宽（宽高比 ≥ 1.6，常见于单列整行卡片）时图例改为右侧竖排、圆心左移，避免正方形圆环两侧留出大片空白，业务 option 仍不得自行指定图例位置；直角坐标网格的上/下/左留白按“有无图例 / x 轴有无轴名 / y 轴有无轴名”取固定行高（图例行、轴名行、轴名列），其余取主题基础留白；环形图圆心随图例存在下移（56%）、半径由主题决定。业务 `legend` 只能声明 `data/show/selected`，`grid` 只能声明 `containLabel/width/height`（内容定几何图）——`top/bottom/left/right/orient/type/center/radius` 一律不得出现（无轴迷你图除外），静态门禁强制；共享层组件（`BarList`）可先给出自己的值，入口只补缺省。**图表画布左右贴合内容**：类目轴标签列用共享 `categoryAxisLabel(names)` 按最长名称量宽并封顶（140px），不得写死 `axisLabel.width`（名称短时会留下大片左侧空白）；指标图例已说明量纲时不重复写值轴 `name`；纯散点图的实体分类图例不能代替轴量纲，须保留两轴名称，由共享入口预留轴名空间；网格左右留白只由共享主题 `grid` 决定，业务 option 不另设 `left/right`。静态门禁强制。**悬停必须聚焦、只从内置选项里选**：共享主题为每种系列类型选定 `emphasis.focus`——`line` 用 `series`（多条线里把被指那条整体拎出来）、`bar/pie/scatter/heatmap/treemap` 用 `self`（只保留被指图元，其余虚化）、`sankey/graph` 用 `adjacency`（只保留相邻流向）；并排对照的 `bar/scatter` 再配 `blurScope: "series"`，虚化只在本系列内发生，同一行的对照系列不受影响；`axisPointer.triggerEmphasis` 关闭（内置开关）——轴指示器只负责提示框与行阴影带，不替整行批量触发 emphasis，否则会与所指图元自身的聚焦互相抵消导致所指的点反而不亮；`none` 禁止（只提亮所指图元不够醒目），任何层都不得手写高亮样式（`emphasis.itemStyle/label/scale`、`blur`、`select`、`axisPointer.shadowStyle`——之前“该突出的没突出”正是自定义阴影带盖住了图元），业务 option 不得设置 `emphasis`；`selectedMode` 这类交互开关允许。静态门禁强制。**分类色板 8 档基色固定顺序、经色觉缺陷与对比度校验（`--ds-color-data-1..8`，亮暗各一组），运行时按明度交替派生浅/深各两环共 40 档（`extendDataPalette`）作为主题 `color` 列表**；按索引取模循环取色拒绝。**图表必须画出全部数据**：任何系列/分片都不得折叠成“其他”（业务图表引用 `common.chart.other` 即拒绝），系列多靠 40 档派生色 + 图例/提示框识别，条目多靠清单滚动；图例统一为内置分页图例（`type: "scroll"` 由共享 `ReactEcharts` 注入——ECharts 按 option 的 `type` 决定组件实现，主题改不了它），条目放不下时单行分页，不与绘图区重叠。**形态按数据的任务选**：比大小用共享 `BarList`（单色横向条形清单：按值降序、条末标值、数值轴在顶部，**所有行都画出、行高 28px、视口固定十行（CHART_HEIGHT）、其余在区域内上下滚动，不把尾部合并成“其他”**——清单类一律上下排列上下滚动：名称横向阅读、条长占满卡片宽度、每屏能放的条目数（10）远多于竖条横滚（每列还得为旋转/截断的名称让位））；随时间变化用折线/堆叠面积；部分与整体一眼看用环形（全部分片按值降序画出）；时段×星期这类网格用热力图 + 单色顺序色阶，**格子必须是正方形**（按容器宽度算格边 = min(可用宽/列数, 可用高/行数)，网格居中，`useElementWidth` 观察容器）；量纲不同的两组指标放同一时间/类目轴上（柱 + 线/点，各自一根轴）而不是拆成两张图；几十个节点的桑基/力导向图不可读，改为按层级取第一跳的堆叠条形。文字只用前景 token，标签不描边；网格与轴线是实线细线。**关系图节点是“带文字的徽标”而不是纯色块**：表面色底 + 语义描边 + 正文文字，状态只编码在描边/底色语义上，当前选中用主色实底反白，异常关系用错误色虚线边——色调表统一由共享 `graphNodeTones` 产出（`components/ReactEcharts/chartTheme`），业务只按语义选择不手写外观；继承/关系图横向按节点布局无限宽、纵向随层级无限高，一律放进 `ScrollRegion` 双向滚动，视口以 `CHART_HEIGHT` 为下限；与操作面板等并排同列时用 `data-chart-fit="fill"` 随行高伸展填满列高（行高由相邻有界内容决定，画布内在尺寸以 contain:size 排除，深层图仍在区内滚动，不把页面撑长）。**图表标题统一由 `chartTitle({ dimension?, metric, form })` 拼接**：维度与指标词由调用方以 `tFragment("common.chart.dimensions.<维度>")` / `tFragment("common.chart.metrics.<指标>")` 传入已翻译片段（项目在自己的 `common.chart.*` 词表声明真实维度/指标名），形态固定为 `common.chart.forms`（排行/占比/趋势/构成/分布/对比），语序由 `common.chart.titleTemplate` 按语言决定（中文“部门调用量排行”、英文“Calls ranking by group”），多指标用 `metricJoiner` 连接，中英混排自动补空格；随时间看的趋势类不带维度词；视图切换的“按…”用 `chartDimensionLabel`。业务页不得手写图表标题文案（`Card/ChartCard` 的 `title` 直接传 `t(...)` 静态门禁拒绝）；维度词必须与数据来源一致（后端按 `department` 分组就叫“部门”）。
- 刷新周期统一通过 `src/utils/cronCycle.ts` 校验和描述，契约与后端 `cronspec.Validate` 一致：只接受标准五字段、后端支持的 descriptor 和 `@every` Go duration，并拒绝未来不可命中的日期。业务页禁止直接导入 `cronstrue`/`cron-parser` 或自写 Cron 正则、字段计数和描述 helper；`cronstrue` 只按需加载中文 locale，不引入全语言 bundle。
- JSON 语法解析与两空格格式化统一使用 `src/utils/json.ts`，领域结构仍由页面或服务契约校验。可编辑 JSON 统一使用共享 `JsonEditor`，由其按需加载本地 Monaco 运行时、worker、主题和选项；页面禁止直引 Monaco 或复制编辑器配置。只读 JSON 使用轻量 `JsonPreview`，不得为预览加载 Monaco。

## FRONTEND-FEEDBACK：通知只属于用户发起的写操作

右上角通知是打断性的：它盖住页头、抢走注意力，因此只在**用户刚刚做了一个会改变数据的动作、而页面上没有别的地方能告诉他结果**时出现。加载成功、页面打开、切换页签、刷新读取都不是“结果”——用户看到内容本身就是结果。

- **唯一入口**：`@/utils/feedback` 只导出三种通知，对应三种且仅有三种允许弹通知的情形：
  | 情形 | 入口 | 文案来源 |
  | --- | --- | --- |
  | 写操作完成（创建/更新/保存/删除/重置/启用/禁用/同步/导出/上传/发布/下线/清空/克隆/复制/发送） | `notifyActionSuccess(action, description?)` | 标题固定为 `common.feedback.actionSucceeded` + `common.actions.<action>`（“删除成功”/“Delete succeeded”），条数等补充信息放 description |
  | 写操作失败（后端拒绝、网络失败、业务返回不成功） | `notifyActionFailed(action, reason?)` | 标题固定为 `common.feedback.actionFailed`，后端/异常原因经 `failureReason` 放 description |
  | 写操作被前置条件拦下或只完成一部分（本地校验不过、弹窗被浏览器拦截、无可保存的变更） | `notifyWarning(message, description?)` | 页面文案 |
  `action` 是 `WriteAction` 枚举（`WRITE_ACTIONS`），查询/刷新/加载这类读取动作不在其中，因此“查询成功”“获取用户信息成功”在类型上就写不出来；页面不再自造“xx成功/xx失败”键，同一动作全站一句话。App 根统一 `topRight`、倒计时进度条与堆叠，按内容生成 key 去重。**关闭策略按类型固定**：只有成功通知自动倒计时关闭（3 秒）；失败与警告常驻（`duration: 0`）须用户主动关闭——错误结果不许悄悄消失。
- **读取永远不弹通知**：页面加载、`useRequest`/`useDataTable` 自动请求、下拉候选搜索、详情/字典/选项读取，成功时静默展示内容，失败时由 `QueryErrorAlert`（有旧数据 `banner`、无数据 `block`）/`QueryFeedback`/`TableQueryBoundary` 在**内容所在位置**常驻展示并提供重试；表单内的候选读取失败用 `Form.Item validateStatus="error" + help` 贴在字段旁；找不到目标对象也是读取失败（抛出后内联展示），不是通知。
- **错误展示的过滤覆盖读取与写操作**：原始错误对象经同一共享提取机制后才可展示，HTTP 5xx 正文及非结构化 4xx 文本/HTML 均不作为用户原因；保留约定的结构化 4xx 业务消息、网络提示和本地校验错误。不得把 `.message` 先转成字符串再传通知，绕过状态与响应体判定。回归须从实际请求包装器产生错误，核对内联读取与写操作通知的最终输出，并保留 4xx 正常拒绝、本地错误及网络失败对照；不以只测提取 helper 替代整条失败传播。
- **请求层不弹通知**：`utils/request.ts` 与 `services/openPlatformService/request.ts` 只把失败收敛为带可展示文案的 `RequestError` 抛给调用方（HTTP 状态、网络、业务 `code !== 0` 一律如此），不再按 `showType` 弹窗，也没有 `skipErrorHandler` 开关；`src/services/**` 不导入反馈入口。写操作处理函数自己 `try { await write(); notifyActionSuccess(...) } catch (error) { notifyActionFailed(action, error) }`，因此一次失败只有一条通知。
- **只由用户动作触发**（静态门禁）：`notify*` 只能出现在用户动作处理函数（`onClick/onConfirm/onFinish/onOk` 及其调用的函数）里；出现在 `useEffect/useLayoutEffect/useMemo` 回调、`useRequest` 的读取函数、组件渲染阶段、模块顶层、`src/services/**`/请求层均被拒绝；`catch` 分支不得调用 `notifyActionSuccess`；业务代码禁止导入或调用 antd `message`/`notification`（含 `App.useApp()` 实例），只有 `utils/feedback.ts`、`utils/antdStatic.ts`、`App.tsx` 例外。
- **运行时门禁** `expectNoUnsolicitedNotifications`：真实页面扫描在加载、切换页签、刷新读取后检查 `.ant-notification-notice`/`.ant-message-notice` 数量为 0——扫描期间没有发生写操作，任何通知都是违规。
- **不是通知的反馈**：复制成功用 `CopyableValue` 自身的对勾 + Tooltip；表单校验用字段级提示；表格行内状态用 `StatusTag`；导出等有下载动作的成功仍需通知（浏览器下载条不在页面内）。

- **最小可展示单元先显示**：同一卡片的主数字、环比与历史趋势不能因共享大接口而被迫一起等待。昂贵次要统计应提供明确的轻量摘要契约，主数字到达立即显示；次要趋势随后按需加载、独立失败和重试。只有展示确实需要组合数据时才等待其全部依赖；导出仍要求当前条件下完整快照。门禁须延迟或拒绝次要接口，验证主信息可见、重试不重复主查询、条件切换拒绝旧响应；性能验收用真实整页并发场景、同数据范围、两浏览器交替多轮比较，不能用单接口或暖缓存耗时替代页面等待时间。

- 远程候选失败必须在控件外显示错误与重试（空候选时输入型下拉也必须可见）；切换字段或候选来源立即失效旧结果，已选值只属于当前字段。
- 切换编辑实体即结束旧草稿会话，A→B→A 不恢复离开的未保存策略或标签。脏值比较保留字符串原始空白，不能用展示格式化或 trim 隐藏真实编辑。

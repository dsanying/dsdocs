# 门禁

自动门禁的注册、分层、执行与人工边界。规范总览与阅读顺序见 [README](README.md)。

## FRONTEND-GATES：自动门禁与人工边界

- **门禁引擎通用、项目差异只在一处**：`scripts/design-governance.mjs` 的规则判断不得出现具体页面名、具体接口名、具体服务层模块名；这类项目绑定参数集中在 `scripts/design-system.project.json`（服务层模块前缀、信息架构的总览/分析页与一级指标、超大候选集接口清单、Ant `Statistic` 例外页），门禁单测的夹具同样从这份配置取值。设计系统因此可以整体复制到其他仓库：换项目只改这份配置，引擎与单测原样生效。
- `manifest.json` 是唯一门禁注册表。每条门禁必须声明稳定 ID、规范规则、领域、输入路径、专项测试、`fast`/`complete` 层级、执行阶段和架构依赖；元门禁拒绝重复 ID/命令、孤儿命令、无专项测试、未知规范章节、不存在依赖，以及门禁脚本实际引用但未登记的规则 ID——诊断输出必须能映射回规范章节。每条门禁登记的规则集合必须与其真实执行的诊断一致，不得为了覆盖登记而挂名无关规则。门禁必须针对可长期识别的同类回归，不得用无差别全仓扫描、一次性文件名单或与目标无关的字符串规则制造成本。
- `pnpm check:affected` 是开发期快速反馈：根据工作区、暂存区和当前分支相对 `origin/main`（可由 `FRONTEND_CHECK_BASE` 显式覆盖）的变化，只串行执行命中输入的 `fast` 门禁及其 `fast` 架构依赖；Git rename/copy 必须同时匹配来源与目标路径。`pnpm check:staged` 只读取 Git index 中已暂存的路径并执行同样的 `fast` 选择，供本地提交前手动运行（仓库不安装提交钩子），不能把长分支相对 main 的全部历史变化带入每次提交。清单、统一 runner、runner/清单元门禁测试、package/lockfile 与验证入口属于共享编排基础设施，变化时失败安全地升级为全部 `fast` 门禁；设计、i18n、单测、TypeScript、ESLint、构建或 UI 的实现与配置只登记为所属门禁输入，不得因“也是检查脚本”而扩大为无差别全量。完整门禁只由合并前的一次 `pnpm check` 或显式 `check:build`、`check:ui` 触发；`pnpm check` 固定按静态门禁、生产 bundle、Chromium / Firefox UI 串行执行，不并发争抢编译器或浏览器资源。
- 颜色可读性由运行时门禁兜底（静态门禁看不到 Ant 内部“实色填充 + 前景文字”的组合）：`tests/ui/forced-wrap.ts` 的 `expectReadableText` 在所有真实页面用例中扫描每个可见文本，按向上找到的第一个不透明背景计算对比度，< 3:1 即失败（禁用态除外）；每个带完整 API mock 的列表页另跑一遍暗色主题（`<slug>-theme=dark`）。实色进度/交互选中态（Steps、DatePicker 选中格、Badge、Slider、Switch 开态）统一映射为 `primary + primary-foreground`，换一次品牌种子即可整体跟随；状态色仍只表达状态。
- `pnpm lint` 是静态门禁阶段，执行 manifest、设计 token/颜色/样式所有权、组件入口、表格配置、滚动边界、Tooltip/图标/链接、placeholder、i18n、TypeScript 与 ESLint 的正反例和源码检查；`pnpm build` 验证生产类型、分包和打包。
- 服务端默认排序不能仅靠前端 AST 元数据验收：每张服务端分页表的默认顺序都需要真实数据库行为测试——乱序插入、随机稳定键、不同分页大小拼接后结果一致，升/降序中的空字符串、纯空格、NULL 均置后，同值次序稳定，公开与管理接口口径一致。依赖真实数据库连接的测试必须显式提供连接串（环境变量）实际执行，未提供连接而跳过的普通单元测试不算数据库行为通过；交付同时核对本地运行服务版本与真实双浏览器顺序。
- 纯逻辑测试统一命名为 `*.unit.test.ts|tsx|mjs` 并由 `pnpm test:unit` 自动发现；不得把 Cron、JSON、页面模型等业务单测塞进设计门禁，也不得为单个文件新增一次性 gate。需要浏览器布局、可访问性或真实交互的验证仍归 UI 门禁。
- 布局回归的边界数据（长短文本、Unicode/NULL、分页尾页、数值/时间边界、关系拓扑）由 UI 测试的接口 mock 以少量成对组合给出，保持确定、可复现；非法领域状态由 API 拒绝测试或隔离 UI mock 覆盖，不得混入共享开发库；不得用随机笛卡尔积替代可复现边界。
- `pnpm test:ui` 先确定性构建独立测试产物，再用 Vite preview 和有限 worker 运行真实 Chromium / Firefox 全量用例；`pnpm test:ui:full` 保留为同等完整检查入口。UI 门禁不使用重试掩盖不稳定，服务就绪有明确超时。测试覆盖共享交互和代表性真实页面的 320/768/1440、长文本、加载/空/错/禁用、重试、局部滚动、Portal 边界、键盘与几何稳定；具体页面机制变化必须扩充对应状态，不用 fixture 自证业务页面。
- 本地迭代不必每次全量：`pnpm test:ui:affected`（等价 `pnpm check:ui --affected`）与 `pnpm test:ui:staged` 按 manifest `uiSpecSelection` 的登记映射，从工作区（或暂存区）变化定向选择 spec——spec 文件自身变化只跑该用例，页面目录变化跑登记覆盖该页的用例，共享组件/设计/i18n/布局/服务/工具等公共层、测试辅助与夹具、以及未登记的业务路径一律失败安全地升级为全量；非前端改动与文档不产生 UI 用例。新增 spec 必须在 `uiSpecSelection.specs` 登记其覆盖的页面输入（清单校验器强制）；新页面或新共享层路径必须先补登记再依赖定向结果。交付或合并前仍须至少一次 `pnpm check` 全量，定向选择只用于开发期快速反馈，不能替代完整验收。
- 浮层需要按最终坐标点击或测量几何时，统一调用 `tests/ui/native-overlay.ts` 的 `waitForNativeOverlayReady`：先确认可见，再等待原生入场类（包含 prepare 阶段）及浮层自身/祖先上的有限动画与过渡结束，不以瞬间稳定的缩放坐标判定就绪。不得增加固定睡眠、重试、超时或关闭业务动画来规避竞态。专门验证入场期间关闭、焦点归还等时序的用例不调用该 helper，保留真实竞态；浏览器回归须证明原生动画确实发生，并验证等待后的点击结果。
- runner 对每条门禁统一输出 `[gate:<id>] START|PASS|FAIL`、耗时和最终 summary，首个失败即停止；不由多个入口重复执行同一门禁。新增、删除或更名 gate 时必须先更新 manifest 元数据与专项正反例，再更新 package script，禁止只接命令不登记适用范围。
- 提交操作的浏览器回归须等待响应处理和用户可见结果完成，再检查数据或结束用例；mock 处理器的请求计数只证明已进入处理器，不能代替操作完成。失败路径同样等待表单恢复可操作或明确失败反馈，避免严格诊断守卫在响应到达前结束测试；不以固定睡眠或重试补偿。
- UI 测试统一收集 console warning/error、pageerror、requestfailed 和 HTTP 4xx/5xx，并校验真实应用页恰好一个一级标题；任一未声明诊断都失败。业务失败态只能通过严格 API mock 按请求方法、完整 URL、状态或失败原因及精确次数登记预期，不能使用 URL 前缀、状态范围、宽泛文案或全局网络白名单；预期未发生同样失败。已确认的上游兼容问题必须由测试服务器启动期转换校验依赖所有者、精确源码模块和稳定证据后统一修正，不能由并行页面分别抓取、改写依赖；业务源码产生的同文案仍须失败。浏览器引擎诊断只可按引擎、精确文案和当前页面来源登记。
- CI 复用公共范围识别的完整可靠路径，通过 `check:ci` 按 manifest 输入与依赖链只选择静态与构建阶段；`ui` 阶段的浏览器验收不进 CI，统一在本地以 `pnpm check` 或 `check:ui` 完整执行，交付前必须运行。普通文档只执行命中的静态门禁，不构建 bundle；未知业务输入仍失败安全地升级为全部非浏览器门禁。CI 入口复用现有公共工作流，不另建重复策略验证任务，也不为浏览器套件配置 CI 专用选择器。不得用开发期仅 fast 的 `check:affected` 替代完整本地验收。门禁零基线，不接受页面、目录或期限豁免；改变规则必须修改统一机制、补齐正反例并重新通过全量检查。
- 静态门禁只拒绝可确定结构和字面量；浏览器验证计算样式、真实截断与位置；人工评审判断信息必要性、语义、组件选择和业务保留。不能用一次性路径名单、关键词堆叠或“测试文件里有字符串”冒充长期约束。

详情键值网格门禁：`inspectScrollSlots` 拒绝详情网格回到单行横滚清单；`expectReadableInformationFields` 在共享夹具及真实详情页检查标签/值、嵌套原子值与标签没有水平溢出、横滚或省略。布局回归以同一宽视口内 220/500/750/1000/1400px 容器验证一/二/三/四列上限，长连续标识完整换行，亮暗主题及 Firefox/Chromium 均执行。


- GitHub CI 保持现有统一前后端工作流；业务重构不附带新增专项工作流或重复检查组织配置。隔离数据库回归与浏览器专项验收按改动范围在本地执行，跳过、缺失和失败不得记为通过；必要的业务断言与设计门禁保留在各自模块。

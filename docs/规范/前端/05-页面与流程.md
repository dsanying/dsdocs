# 页面与流程

页面名同源、列表 → 详情 → 编辑、保存条、数据页面信息架构。规范总览与阅读顺序见 [README](README.md)。

## FRONTEND-NAVIGATION：页面名、查看与编辑流程

- **对象的查看与编辑只有两档机制，按“点进去能不能看到列表给不了的东西”判定，不按字段多少、不按挂在哪个页面**：
  - **判定**：对象只要具备以下任一项就是**业务实体**，否则是**配置条目**——① 派生只读信息（用量、余额、有效权限、继承来源、统计、同步结果）；② 从属集合（记录、明细、调用历史、命中项）；③ 编辑以外的状态动作（启用 / 禁用、发布 / 撤回、重置、同步）。按本项目真实对象判定并记录；一个列表页的每个页签各算一页、各自判定。
  - **两档的完整形态**：

    | | 配置条目 | 业务实体 |
    |---|---|---|
    | 路径 | 列表 → 右侧抽屉编辑 | 列表 → 详情 → 编辑页 |
    | 列表内容 | 除密钥外**全部字段**（量大且平时不看的走“查看”抽屉） | 识别 + 状态 + 1～2 个关键指标，最多 8 列 |
    | 行内操作 | 编辑（打开抽屉）+ 删除 | 详情（第一个）+ 删除等危险操作 |
    | 新建 | 工具栏“新建”打开同一抽屉 | `<列表>/new` 页面，保存后进入该对象详情 |
    | 详情 | 无 | `EntityDetailPage`：页头（对象名 + 状态 + 编辑在前的状态动作）+ 摘要条 + 字段网格（覆盖编辑表单的全部字段与只读元数据）+ 页签 / 只读明细 |
    | 编辑 | `DrawerForm`（统一宽度） | `EntityEditPage`（表单 + 状态化编辑动作），保存后进入详情 |
    | 跨页深链 | `?editXxxId=` 打开该条目的编辑抽屉 | `<列表>/detail/:key` |

  - **列表通用**：识别对象用名称、标题等业务标识，不放无业务含义的自增 ID 列（ID 只在详情页字段网格出现）；起止时间合成一列，一张表只留一个时间列；含义相关的值合并展示（单位并入所修饰的列）。
  - 配置条目的弹窗：`ModalForm` 只承载不改动对象的一次性工具动作（查询、导出，`submitter.action` 为 `query`/`export`）；只有自定义页脚的多步向导（目录同步、批量上传）才直接用 `Modal`。
  - 业务实体的细则：名称是普通文本、不兼作详情链接；名称链接（`variant="name"` + `LinkOutlined`）只用于引用别的对象；状态动作都在详情页头；不可修改字段在编辑页用 `ReadonlyValue` 只读展示；新建只走 `/new` 页面，一次性展示的结果（如 API Key 明文）在新建页保存后弹出、只存组件状态；跨对象的关系直接在相关对象的详情里展示（如账号详情的关联规则页签列出匹配的规则），不另做输入查询的工具弹窗；实体 CRUD 路由使用 `<列表>/new`、`<列表>/detail/:key`、`<列表>/detail/:key/edit` 三种形态，同一组件多形态挂载用 `lazyWithMode`。来源用户由同步而来，只有详情没有编辑；目标项目按真实身份与权限契约决定用户是否可编辑。
  - 静态门禁：实体带参数路由不是 `detail/:key[/edit]` 形态（存量非 CRUD 工作流或作用域路径须在 `design-system.project.json.navigation.businessRoutes` 登记实际路由定义、业务契约与原因；门禁核对真实路由，不接受无实现声明）、页面用 `AppPage` 的 `content`/`tabList` 自拼详情、页面直接摆 `SaveBar`、列表行里跳转到编辑页的“编辑”（无例外）、名称兼作详情链接（`variant="name"` 配 `EyeOutlined`）、详情入口文案不是“详情”、`Modal` 包 `Form` 且没有自定义页脚、表格超过 8 列、一张表两个以上时间列、有详情入口的行里出现非危险的其他按钮、含对象表单（`DrawerForm`，或非查询 / 导出的 `ModalForm`）的文件自身或其直接引入的同目录模块有详情入口（`inspectEntityListForms`，按文件判定，页签各算一页），（另：列表里的自增 ID 列、只有字段网格而没有摘要 / 页签 / 状态动作 / 只读明细的 `EntityDetailPage`）均拒绝。
- **关联字段直接前往关联对象**：列表、详情或明细中引用其他已有详情页的对象（如条目、分组、资源），使用共享 `ActionLink variant="name"` 与 `LinkOutlined`，路由标识必须编码，空值显示 `-`；本列表主体名称仍由独立“详情”操作进入。纯字段内容不另插无关工具跳转。项目在 `design-system.project.json` 的 `entityReferenceColumns` 登记已确认的关联列，AST 拒绝无共享链接的纯文字回退，浏览器核对链接地址及可达性；是否有真实详情页、是否属于关联而非当前主体仍须人工确认。
- **不放指向不存在功能的入口**：没有对应页面或能力的菜单项、按钮、链接（如“个人中心”“个人设置”）直接不做，不用跳回首页或空页面占位；侧栏底部的当前用户只做身份展示（头像用名字首字符 + 主色底 + 反色文字，取不到字符退回通用图标；名字过长在自身范围内左右滚动），不是下拉菜单。静态门禁拒绝 404 页以外的 `navigate("/")`。
- **系统内部键不让人填**：只给系统对齐数据用的标识（如通知页面 ID——问卷答案的 `slide_id`、发布后锁定判断按它对齐；问卷选项值——答案按它记录）由前端按固定格式编号（通知页面为 `p{n}`，选项为每题内的 `opt{n}`），编辑界面不出现输入框也不做必填 / 重复校验：已保存过的键永远不变（拖动排序不重新编号，否则已有答案会对到别的页上）；本次新加、尚未保存的项按当前顺序从“已保存键的最大编号 + 1”起连续编号，保存前随排序调整、保存后固定；起点取最大编号而不是项数，删除后再加不会撞号；旧数据缺失或重复的键加载时按新项编号。多项有序内容（通知页面）用“大纲 + 单项编辑”：大纲列出全部项的序号、标题、类型与待完善标记并可拖动排序，点一行编辑该项，不把所有项的表单叠成折叠面板。
- **页面名只有一个来源——导航树**（`routes/index.tsx` 的 `label`）：侧边栏菜单项、面包屑、一级标题都从它取，三者永远一致。匹配由 React Router 的 `matchRoutes` 完成，静态段、参数与通配段的优先级同实际路由，长参数名不得抢占静态页。详情、新建、编辑、子页以 `hideInMenu` 写在所属分组里，由 `nestHiddenRoutes` 挂到路径前缀最长的列表项下：面包屑是完整层级（资源管理 / 规则列表 / 授权配置），侧边栏高亮所属列表。`AppPage` 的 `title` 只给导航树给不出的名字——同一路由的新建/编辑两态（“新建标签”）、详情页的对象名（资源名、规则名、成员姓名），它同时替换面包屑末项与一级标题；普通页面不传，改名改导航树。**末项之前的面包屑都能点回去**：节点地址代入当前地址的动态段（详情项链到“这个对象”的详情），只有侧边栏分组（本身没有页面，如“配置管理”）不可点；编辑已有对象时 `EntityEditPage` 传 `objectName`（与详情页标题同一个名字），面包屑上一级显示对象名而不是泛称“××详情”（配置管理 / 规则列表 / 全职员工类 / 编辑规则），读取前回退到导航树名字。标题旁的小型入口（规则列表的拒绝计数）放 `status` 槽位，不拼进标题。静态门禁拒绝 `<AppPage title={t("...")}>` 固定标题；静态门禁拒绝带 `query` 却没有 `objectName` 的 `EntityEditPage`；运行时门禁 `expectConsistentPageTitle` 检查一级标题 = 面包屑末项、侧边栏高亮项出现在面包屑里、除第一项的顶层菜单分组外，末项之前的面包屑都必须是链接。
- **路由身份来自已提交的导航状态**：页面 key 只能随真实路由或已登记的上下文版本变化；语言、主题及普通重渲染不能重新读取 `window.location` 拼接挂载 key。业务流程调用 `history.replaceState` 时同步其既有路由状态，不能让下一次语言切换才补偿身份变化。验证先完成真实详情进入/返回，再在当前详情通过语言控件中 → 英 → 中往返，断言同一内容节点、已输入值和打开状态保持、接口调用数不增加；合法返回或 popstate 的重新读取仍按原流程发生。不能删除 key 或忽略真实导航来修复重挂载。
- **编辑动作由状态决定，位置由滚动需求决定**：持久化编辑入口未修改时，退出由容器自带入口承担——整页编辑用页头返回键/面包屑，弹层用头部 ×——正文与页脚不重复放关闭按钮（干净态 `SaveBar`/`FormFooter` 不渲染，抽屉/弹窗不留空页脚条）。有未保存修改时只显示 `取消`（`common.actions.cancel`、`CloseOutlined`）与 `保存`（primary、`SaveOutlined`）；查询、导出等一次性动作的弹窗页脚保留取消配对主动作。表单级动作不使用“还原/撤销/重置”命名，不常驻禁用的保存按钮；成熟编辑器原生撤销/重做保留。关闭退出当前编辑容器；取消丢弃本次全部草稿并取消待提交附件，不提交数据，按容器语义退出或回到已保存状态。历史版本采用属于该功能的明确动作名称，不复用表单取消。保存中阻止重复提交、取消和关闭；失败保留草稿、修改状态和重试入口；成功更新基线，回到关闭态或按业务流程离开。未提交的新内容属于修改；查询、导出、确认危险操作等一次性动作不属于持久化编辑，不按脏状态隐藏其执行按钮。
- **区域收尾操作统一靠右**：表单提交、分步向导的预览/上一步/确认、集合编辑区域底部的添加等收尾操作，置于所属区域内容之后，用共享 `ResponsiveActions` 默认靠右；主动作在最后（右侧），辅助动作在其左侧。弹窗/抽屉优先复用原生页脚或共享表单页脚，不为了对齐新增固定定位。窄屏允许整项换行并保持靠右，操作不能越过所属区域边界。查询工具栏按钮跟随筛选条件，字段旁局部操作与表格行内操作保持就近布局，导航、选择项不按收尾按钮处理。浏览器门禁核对弹窗/抽屉页脚与真实分步上传的宽窄屏右边缘及步骤切换后的操作顺序。
- **完整 Ant 编辑页复用共享 `SaveBar`，不自造第二套动作组**：公开接口为 `dirty/onSave/onCancel`；`SaveBar` 只在脏状态渲染取消与保存，干净状态不渲染任何动作（页头返回键承担退出），实体编辑由 `EntityEditPage` 统一接线。默认 `placement="inline"`，在正文之后正常排列；一屏编辑区按剩余动态视口伸缩，长正文在编辑器内部滚动。只有页面/窗口正文确需纵滚、操作会离开视口时才选 `placement="footer"` 使用共享底部槽位，并为操作保留布局空间；不因“编辑页”身份默认固定，不在干净状态留固定条、阴影或空占位。窄屏、短视口、错误增加内容时可自然增高，不能裁切、缩字号或压缩点击区域。Modal/Drawer 使用原组件正文与 footer，不加网页悬浮条。
- **脏状态来自已保存基线**：表单使用 `useFormDirty(form, baseline)`，非表单草稿使用 `isSameValue(draft, loaded)`；异步装载与保存成功同步更新基线，子编辑器挂载不得制造假脏。抽屉/弹窗编辑在 `initialValues` 给出完整基线，异步装载或额外非表单草稿显式传 `dirty`。静态门禁拒绝业务层自行摆保存/还原动作；类型要求共享编辑动作必须提供取消处理器。运行时检查干净→修改→取消、保存中、成功、失败、新建、校验/权限未满足及局部滚动；测量默认正常流与有实际滚动的底部模式、操作不遮挡内容且短窄视口可达。静态门禁不能证明真实 dirty、滚动或取消无写入，这些必须由行为测试验证。

## FRONTEND-INFOARCH：数据页面信息架构

有数据总览/分析需求时按两个职责区分：**数据总览**（`/overview`）回答“现在整体怎么样”，**深度分析**（`/analysis`）回答“为什么、具体是谁/哪个”。同一张图不得同时出现在两页；判断一张图放哪里只看下面的准入条件，不按“好看”或“顺手”摆放。

- **数据总览的准入**：展示无需页内交互就能理解的整体一级指标、时间趋势与主维度切片。一级指标由目标业务确认并登记 `design-system.project.json` 的 `overviewMetrics`，页面路径也在该处登记；没有这些页面时用 `infoArch: { applicability: "none", reason: "真实业务原因" }` 明确记录不适用，不登记不存在的占位目录；配置页面路径必须匹配实际源码。版式例子是三个 KPI 卡（总量、请求数、活跃数，各带环比与 7 点迷你趋势）、指标趋势，以及按服务/分组/类别维度的指标切片。这是版式与职责参考，不要求目标项目具有相同业务指标。派生效率、时段热力、交互明细和双指标对比进入深度分析。全局查询条件由全部区块共用；固定壳与分块并发由页面组合 Hook 承载——主数字先渲染，次要块独立失败重试。
- **深度分析的准入**：需要对照、明细或派生/效率指标的内容放在这里。目标定义共同的全局条件，每个页签按“概览卡 → 图 → 表”自上而下：`SummaryStrip` 给总量、图给分布与对比、`TablePanel` 给可排序分页的明细，一个页签内图不超过 6 张。
- **深度分析的页签按分析对象（主体）划分，不按图表类型划分**，对象示例（本项目按真实领域决定）：
  - **使用者分析**（对象 = 使用者）：时段请求数分布（热力）、身份占比、分组指标与活跃使用者对比、使用者统计表。
  - **资源分析**（对象 = 资源）：资源概览卡、资源统计表、不活跃资源表。
  - **服务分析**（对象 = 服务）：服务概览卡、总量/请求数趋势、请求数排行、单次均值构成、请求数与均值对比（服务维度排行属于总览切片，不在此重复）。
  新增页签只能是新的分析对象（如“服务分析”“分组分析”），不得出现“图表”“报表”“其他”这类按形态或兜底命名的页签；一个对象的内容不足一屏时并入最相近的对象页签，而不是单开页签。
- **图表落位的判定顺序**：① 指标是本项目已登记的一级指标且维度是主维度且不需交互 → 总览；② 否则按分析对象进对应页签；③ 同一对象内先概览卡、再趋势、再排行/占比/构成、最后对比与明细表。静态门禁 `inspectDataPageArchitecture` 按 `chartTitle` 槽位判定：同一组（维度 + 指标 + 形态）同时出现在两页拒绝；总览出现已登记一级指标以外的指标拒绝。
- **命名与形态**：标题一律 `chartTitle`（维度 + 指标 + 形态），形态按 FRONTEND-DATA 的选型规则；页签名 = `<对象>分析`，区块标题不重复页签里已有的对象词（页签内的图仍以对象词开头是因为标题独立成句，允许）。

- **层级/继承关系用“分层层级图 + 当前节点操作面板”，不用力导向关系图**：标签继承、分组嵌套这类“谁属于谁、有几层、哪里成环”的信息，默认用**自上而下的分层图**表达（ECharts `graph` + `layout: "none"`，位置由纯函数按“到根的最长路径”定层、同层按父列序重心排列——只由数据决定，不是力导向那种随机摆放；根在最上、箭头父→子、成环边红色、节点是按文字定宽的圆角框；图例用共享 `ColorLegend`——色块直接引用图上取色的同一个 `--ds-color-*` token，禁止拿状态标签等另一套配色去“模仿”图例，否则图例与图对不上），图右侧是**当前节点操作面板**（状态/标识/关联项数 + 直接父、直接子两张小表，在这里添加/删除关系、点行切换节点；点图上的节点即切换当前节点，当前节点在图上用主色实底标出，并以库自带的 `highlight` 动作常驻悬停态——鼠标不在别的节点上时只点亮它与相邻节点、其余虚化，悬停别处交给 ECharts、移开后恢复）；不再另附整表把所有标签再列一遍（图 + 当前节点面板已经覆盖，重复信息只会拉长页面）；**节点定位用可搜索单选 `Select`，不用自由文本过滤**：下拉选项即图中全部节点，与图上点选、面板行点击、深链定位共用同一份"当前节点"状态——任一路径选中都同步反映到其余各处（下拉显示值、图上主色实底与邻接聚焦、右侧面板）；不做关键词链过滤（几十个节点的图上填空定位没有判别力）。添加关系永远从某个标签发起（表格行 / 图节点的“添加父节点 / 添加子节点”），弹窗只选另一方，锚点只读展示，候选已排除自己、已有关系和会成环的标签——不提供“同时选两端再交换”的通用新增。标题只叫“标签继承”之类的关系名，不再叫“关系图”；布局与候选过滤抽成纯函数（按“到根最长路径”定层、同层按父列序重心排列、候选排除自己/已有关系/会成环项），页面组件只做接线。

# 文案、国际化与可访问性

必要信息与术语、双语目录与共用词、时间格式、可访问性。规范总览与阅读顺序见 [README](README.md)。

## FRONTEND-COPY：必要信息与术语

- **说明文字只保留必要要求**：字段说明（标签旁问号/搜索规则/弹窗提示）只写格式限制、取值范围、必填依赖、空值含义与危险影响（如“只支持字母、数字、- 和 _”“留空表示永不过期”“删除后无法恢复”）；不写操作教程、默认行为解释、系统内部机制或“可手动调整”“会同步更新”一类说明性文字，也不自创上游没有的字段释义。字段释义只能来自上游数据字典/库表注释原文。
- 固定单位、文件后缀和协议前后缀由控件只读槽位显示，输入仅编辑真实可变部分，保存时由统一转换接回；不能把固定 `.md` 等后缀放进可修改范围，也不写说明句解释显然不可修改的属性。是否固定由本项目真实格式契约决定，不将示例后缀强加给其他格式。没有明确旧使用者或迁移契约时，不增加旧网址跳转、兼容别名、双写或 fallback；真实数据迁移先登记边界与退出条件。
- 删除后是否影响理解、判断或下一步，是信息必要性的唯一标准。辅助文案必须增加前提、影响、边界、来源、时效或下一步；重复标题、字段、按钮、状态或显然操作的内容删除。
- 页面只展示真实对象、当前事实和可执行操作，不保留口号、英文眉题、功能复述、实现说明、假操作、假统计、装饰示例或无依据安抚。
- 查询条件一律“标题：输入框”：字段名由 label 表达；条件变更不触发请求，只有统一的一个查询按钮（或回车）提交查询。全部输入控件一律没有 placeholder：业务 TSX 的 `placeholder` 属性与 `fieldProps.placeholder` 等控件配置由静态门禁无条件拒绝（业务数据字段不受影响），Ant locale 里的日期起止、搜索等默认占位由应用根递归置空，不存在任何例外。移除 placeholder 后必须保留可见 label 或 `aria-label`；格式限制、示例与留空含义放在 `Form.Item tooltip`、`HelpTip` 或 `SearchInput hint` 的问号内；校验错误、读取失败、状态前置条件、真实结果与风险保持可见，位置遵循 FRONTEND-TOOLTIP。
- “查询”表示提交服务端条件，“搜索”表示过滤已加载数据。同一对象、状态和动作使用统一术语；失败文案写清动作与对象，风险与影响不得因精简删除。

## FRONTEND-I18N：双语目录、共用词与动态键

- **任何可见文案都不得写死**：JSX 文本、可见属性（label/title/description/extra/help/content/tooltip 等）与 Ant 反馈里出现汉字或两个及以上字母的拉丁词（品牌名 `基线系统`、术语 `ID`、语言名 `English`、单位词一样）都必须来自 `t()`；只有配置值（className/size/variant/value/key/mode 等）和比较运算里的字面量不算文案，静态门禁按此判定。
- **字典是词表 + 拼接，同一个词只在字典里出现一次**：复合文案（“权限搜索”“用户详情”“该成员暂无权限”）不写成独立文案，而是用 i18next 嵌套 `$t(key)` 引用原子词条拼出来：zh `"$t(common.vocab.search)$t(common.vocab.permission)"`、en `"$t(common.vocab.search) $t(common.vocab.permission)"`，语序、空格、单复数由各语言文件自己决定；插值模板（`"{action}{object}"`、`"共 {count} 条"`）同样不含任何词条字面。门禁按内容判定，与具体词无关：任一值的字面片段若完整包含另一个键的文案（中文按子串、英文按整词；全大写缩写严格大小写，其他词大小写不敏感），即拒绝并指出应引用的键；被引用的词条必须位于 `common.*`（`common.vocab.*` 通用词、`common.terms.*` 术语、`common.actions/objects` 动作与对象、`common.chart.*` 图表词表、`common.calendar/language/request/feedback`），引用必须存在且不得循环。**任一语言里同一段文案只能属于一个键**（英文大小写不敏感）：同一概念合并为一个键，不同概念译文必须区分（“职务/标题”不能都是 Title），页面标题直接复用菜单键 `menu.*`。`pnpm i18n:compose` 是唯一的拼接工具：展开旧引用 → 英文词条小写化 → 最长词优先替换为引用，幂等；新增或改写文案后先跑它再跑门禁。
- **英文词条小写、排版由运行时统一**：字典里的英文除专有名词、缩写与句号后的新句外一律小写（`Add user` 存为 `add $t(…user)`），`i18n` 的 `typeset` 后处理器在最终展示时把整段首字母大写并在汉字与拉丁字母/数字之间补空格（“查看 ID 列表”）；页面与图表标题不得自行处理大小写或中西文间距。运行时再拼接（`t(template, { object: … })`、`chartTitle`、`notifyAction*`）取片段必须用 `tFragment(key, options?, translator?)`（跳过后处理，避免片段先被大写成 “Add Condition”），`tFragment` 只能作为其它翻译调用的插值参数或拼接模板的输入，不得直接展示；作为插值参数的翻译调用不得是普通 `t()`，静态门禁强制。固定语言词表 factory 把当前 `t` 作为第三参数传入片段；条件、空值与逻辑分支中的片段仍须最终成为外层翻译插值，不得直接展示。
- **文案只存在于字典**：`t()`/`Trans` 不得携带 `defaultValue` 或第二个字符串参数（门禁拒绝），代码里只有键；键必须在两份字典里都存在，未使用键是错误。双语内容种子（通知页面的中英文默认内容）用 `bilingualText(key)` 一次取出 `{zh, en}`，不为每种语言各存一份键。
- 展示用的字符串常量（坐标轴类目 `xAxis/yAxis.data`、清单类目 `categories` 等传给图表/清单的字面量数组）与 JSX 文本同属可见文案：数组元素含字母/汉字词即拒绝，必须来自 i18n 词表（如 `common.calendar.weekdays.*`，后端 0=周一 … 6=周日 的索引只在前端映射成当前语言）或数据本身（`rows.map(r => r.name)`、按模板生成的 `0:00…23:00`）。
- **时间只有一个入口、一个时区**：项目业务时区固定为 `Asia/Shanghai`（无偏移输入只有在接口确认它表示上海时间时才可如此解释；后端不同契约先在 service 边界转换为带偏移绝对时刻），前端 `utils/dateTime` 是唯一入口——`now()` 取业务时区的现在，`parseServerTime()` 解析任何来源的时间（不带偏移的接口串按业务时区、带偏移/毫秒/Date 只换算），`formatDateTime/formatDateTimeMinute/formatDate/formatMonthDay` 展示，`toOffsetDateTime()` 提交（总带 `+08:00`），`rangeOfRecentDays()` 算日界；**展示日期一律用 `/` 分隔**（`2026/09/16 15:47`、`09/16`），DatePicker/RangePicker 的 `format` 只取 `DATE_FORMAT/DATE_TIME_FORMAT/MONTH_FORMAT/YEAR_FORMAT/MONTH_DAY_FORMAT` 常量，图表类目等接口原样给出的日期桶（`YYYY-MM-DD`/`YYYY-MM`）经 `formatDateLabel()` 换分隔符，提交给后端的格式不受影响；业务代码自写 `YYYY-MM-DD`/`MM-DD` 展示格式串由静态门禁拒绝；现存接口确需无偏移日期或不同传输时区时，以 `design-system.project.json.transportModules` 登记纯 TypeScript service 转换模块、导出序列化/解析函数、真实 import 及接口契约，门禁核对源码与格式约定并拒绝把序列化结果直接作为可见文案。转换模块不得包含 JSX 或 UI；接口往返测试覆盖纽约设备时区、日期/月/年边界及服务器实际时区，不能靠改后端时间格式使迁移通过；不同时区的设备看到并提交的是同一份时间。业务代码只能 `import type { Dayjs }`，不得直接 `dayjs()`、`new Date()`、写死 `+08:00`（静态门禁强制；`Date.now()` 只作临时 id 不受限）；单元测试在 `TZ=America/New_York` 等外时区下跑同样通过。
- 语言字段说明按当前界面本地化：中文目录的 `common.language.enUS` 为“英文”、`common.language.zhCN` 为“简体中文”；语言切换的 `EN`/“中文”使用专用短词条，不能拿外语自称代替字段标签。词表门禁核对展开引用后的语言名称，真实页面分别断言中英文标签与校验提示；中文括注使用全角括号。
- 语言集合只有 `zh-CN` 与 `en-US`，fallback 为 `zh-CN`；检测顺序为 localStorage（键 `dsdocs-lang`）→ navigator → htmlTag，语言切换只经 `i18n.changeLanguage`，统一 i18n 模块在初始化和切换时同步 `html.lang`（不依赖 localStorage 可写），语言切换入口显示目标语言自身的写法（中文界面 `EN`，英文界面“中文”，文字标 `lang`）。侧栏使用 `SidebarMenu` 语言操作项，独立顶栏使用 `SelectLang`，均调用同一 `i18n.changeLanguage`。上下侧栏和账户规范分别归 FRONTEND-LAYOUT 与 FRONTEND-COMPONENTS。Ant `ConfigProvider locale` 与 dayjs locale 必须从 `i18n.language` 经统一映射派生并跟随切换；页面不得写死单一语言，不得使用 `toLocaleString("zh-CN")` 等硬编码区域格式，面向用户的时间展示统一经 `src/utils/dateTime.ts`，数字格式随当前 locale。
- 插值统一使用单大括号 `{name}`（由 i18next prefix/suffix 全局配置提供），翻译值不得包含 HTML 或可执行内容；目录父子键冲突时父值放 `_self` 节点，不新增私有转义约定；由 dayjs locale 生成的相对时间等框架文案不进目录。
- 英文必须是符合母语表达习惯的自然英文，不得逐字直译中文；两种语言维护同一术语体系，API、Cron、OAuth、RBAC 等专有名词两语言保持一致，不音译、不另造同义词。同一对象、动作、状态在两份目录中的键路径必须语义对应。
- 中英文目录必须拥有完全相同的键、叶值类型和插值变量；所有在用键都有双语值，所有目录键都有可证明调用方。未使用键是错误，使用 `pnpm i18n:prune` 在其他错误为零时同步清理两份目录。
- **类型、静态与页面验证分层防遗漏**：`src/i18n/i18next.d.ts` 从实际字典声明 i18next `resources` 并启用 `strictKeyChecks`；普通翻译调用及共享 `tFragment`、`bilingualText` 包装器只接收合法叶子键。动态来源使用由字典推导的 `TranslationKey` 或有限字面键集合，不接受任意字符串，不用类型断言、忽略诊断或白名单绕过。类型回归必须证明合法调用通过、错误键与任意字符串编译失败、`defaultValue` 不能掩盖错误键；AST 门禁继续验证双语结构、插值、引用、可见文案和动态键登记，浏览器验证实际展示与语言切换。三层各负其责，编译通过不能替代双语页面验收。
- 默认使用字面 key 或可穷举的条件 key；条件 key 的每个分支分别满足其插值变量契约。只把 `react-i18next` 的 `useTranslation` 返回值、项目显式翻译函数 props 契约（含内联对象类型、导入别名与解构别名）及其可追踪别名/转发包装器视为翻译调用；普通同名 `t` 不参与扫描，真实翻译绑定也不得被内层同名可调用值遮蔽。`Trans` 的插值通过 `values` 或直接及嵌套文本位置的 `{{value}}` 子节点显式提供，子组件属性中的同名对象不算翻译插值。动态 key 只有框架配置或统一字段渲染等真实需要时才允许；`src/i18n/dynamic-keys.json` v2 必须登记每个调用的 AST 行列锚点、精确调用次数、理由、完整键集，以及限定在唯一 AST 根节点内的数据源选择器和匹配次数；`dataFlow` 还必须证明所选调用实参到目标函数参数，或组件数据 prop 到翻译 callback 参数的直接关系，后者的数据 prop 与目标组件都必须解析到登记模块、导出名、数据源文件及 AST 根对应的真实 import binding，局部同名组件或变量不能替代。调用移动、复制、进入经括号、类型断言、`satisfies` 或非空断言包裹后仍可静态判定的假分支或 `while/for` 假循环，或在同一锚点下用无关同名属性/调用伪造数据源都会失败；安全常量求值包含 `undefined`、`void`、`BigInt`、`NaN`、一元运算及常量算术、比较和逻辑表达式，并尊重局部同名遮蔽。
- JSX 直接文本、文本表达式，以及 `tooltip`、`title`、`placeholder`、`label`、`description`、`help`、`extra`、`emptyText`、`content` 等可见属性中的中文必须来自 i18n；静态对象、属性访问、动态索引和 JSX spread 流入这些位置时同样检查。Ant Design `message`（含项目主题安全封装、namespace、方法别名、`useMessage` 与 `App.useApp` 实例）的反馈文案也受控；注释、未流入可见位置的业务数据、本地同名 API 和翻译调用内的中文 `defaultValue` 不误报。
- 通用裸动作放 `common.actions`；跨页面同义对象放 `common.objects`；“动作 + 对象”使用 `common.actionObjectTemplates` 的 `{object}` 插值，让各语言独立决定词序，模板名必须有对应裸动作且每种语言都包含 `{object}`。真实 Ant Button import、别名、namespace，以及经递归 `const` namespace/property/解构形成的不可变别名，其普通 children 和 `children={...}`，动作 label/text prop 与带执行处理器的菜单项，不论位于 `pages`、`components` 或其他命名空间，都不得保留与 common 完全同义的分叉；静态 JSX props 和菜单 handler spread 按运行时从左到右覆盖顺序展开，getter/setter/accessor 同样参与覆盖，未知 spread 只使其之前的结论失效，不臆测其内容。名称相似但没有受控 Button binding 的非动作组件或可变别名不据此判定。与现有模板、对象在中英文均可精确组合的完整短动作也必须复用模板。禁止在代码中用 `+` 或模板字符串拼翻译；包含风险、结果、状态变化或其他业务含义的完整句不按字面相似强拆。
- Ant 已提供的分页、确认等框架文案由 `ConfigProvider locale` 提供；查询按钮由共享 `QueryForm` 引用 `common.actions.query`，不在页面重复维护。危险确认、状态变化、成功失败、业务影响等完整语义不能强行归并为裸动作。
- 调用点必须提供目录声明（含引用词条沿途）的全部插值变量。`pnpm i18n:duplicates` 仅报告同业务命名空间的重复/近似候选；只有语义、权限和生命周期一致时才合并——文案相同的键在门禁里已是错误，合并或改译由人决定。

- 金额展示统一使用 `utils/number.formatAmount` 或 `formatCurrency`，普通金额最多三位小数；非零绝对值小于 0.001 时采用最多三位尾数的科学计数，避免显示成零。序列化、精确计算、原始 JSON 与复制仍保存原始十进制精度，禁止先 `Number` 转换金额字符串再调用精确小额展示。

## FRONTEND-A11Y：可访问性与交互状态

- 页面有唯一主标题；表单有可见 label；图标按钮有可访问名称；状态不只依赖颜色。所有操作键盘可达，焦点可见，弹层关闭后恢复触发点；自定义滚动区有 region 名称并可聚焦。
- 普通文字对比度至少 4.5:1，大号文字和关键控件边界至少 3:1。禁用状态仍可辨识；错误、加载和成功反馈使用正确语义或 live region。
- 动效遵守 `prefers-reduced-motion`；不添加无业务价值的入场、脉冲、滚数和扫光，也不用动画掩盖加载或造成布局偏移。
- 落实边界：唯一主标题由 UI 门禁逐页强制；键盘路径、焦点恢复与滚动区可聚焦由 UI 门禁抽样验证；对比度数值由真实页面运行时门禁验证；label 可见性与动效克制由共享层 token 设计保证并依赖人工评审，不设静态门禁。

Dayjs 的 `zh-cn/en` locale 由 `src/i18n/index.ts` 显式注册、初始化并随 `languageChanged` 同步；月份、星期和相对时间不能混用默认英文。`formatRelativeTime` 对已经存在的 Dayjs 值也取当前语言，数字日期格式、Asia/Shanghai 边界与带偏移提交保持时间入口契约。实际模块单测验证两语言往返、既有时间值的语言更新、不可写存储和无浏览器全局，不只验证注释或初始化代码存在。

中文词典的权限效果“允许”“拒绝”复用 `common.vocab.allow/deny`，不得残留界面英文 allow/deny；门禁检查展开嵌套引用后的值。接口值与业务数据不属于词典文案，不因这条规则改写。

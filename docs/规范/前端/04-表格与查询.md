表格列宽与单元格、列表列数、多选约束、查询区、权限点列表。规范总览与阅读顺序见 [README](README.md)。

## FRONTEND-TABLE：表格、列表与查询

普通字符串与数值由共享 Table 自动放入独立 AtomicValue 槽位，不能只依赖 td 的 overflow：Firefox 必须验证真实 scrollLeft 和末尾文字的几何可达性。 自定义 JSX 的关联名称、复合数值同样需要共享的独立滚动槽，不能因外层已经声明 overflow 而省略。详情键值信息按第 02 章完整折行，不属于横滚槽。图标与关闭入口保持固定，文字完整可达；宽屏放得下时不截获滚动，窄屏真实溢出时在所属区域滚动。浏览器门禁除完整 Chromium 外，固定执行 Firefox 表格滚动契约和刷新周期真实页面回归；仅检查 overflow:auto 或 data-overflowing 不代表内容能滚动。横向滚动条由共享 scrollbar.css 统一：标准路径 thin，支持 WebKit 伪元素的路径使用 --ds-space-2（2px），透明轨道与主题边框色滑块，不使用粗滚动条遮挡内容。虚拟候选列表同样使用 2px 显色滑块与透明轨道，保留较宽的透明拖拽命中区域。候选文字真实溢出时独立处理横向滚轮与 Shift＋滚轮，普通纵向手势继续浏览列表；不得让虚拟列表截获横向手势。双浏览器门禁必须用真实鼠标正反滚动及拖拽验证，不能只赋值 scrollLeft；同时覆盖宽窄屏、亮暗主题、其他候选位置与完整可见性。

- **时间范围与日期选择只有一个入口：共享 `RangePicker`/`FieldDatePicker`**（`components/ui/RangePicker.tsx`）——原生 DatePicker 面板在窄屏会弹出视口外（双月面板约 560px、带时间的单月面板更宽，320px 下必然被裁），且原生只限外层宽度不够（内层面板容器会裁剪溢出），必须裹成滚动容器再在视口内平移；共享封装统一弹层边界（`classNames.popup.root` 限宽 + `panelRender` 滚动包裹 + `popupAlign` 的 `shiftX`）、展示格式与近 7/30/90 天快捷预设（按业务时区重新计算，经 `presets` 可覆盖）。业务层不得直用 `DatePicker`/`DatePicker.RangePicker`/解构 `RangePicker`（静态门禁拒绝，含别名与 namespace 形态）。需要全局日期范围等复合控件时在共享 RangePicker 之上追加标签与窄屏堆叠布局；不得把“自定义”状态放进无动作的下拉选项，或再用独立预设控件根据日期反推模式。UI 门禁覆盖快捷范围、手动日期、双语与窄屏，并检查弹层边界、提交的日界与请求参数。

- **权限点列表只有一个视图 `PermissionPointTable`**（`src/components/PermissionPointTable`）：权限字典、授权编辑、标签管理、权限诊断、关联详情等凡是“列出权限点”的地方，统一为“搜索（空格拆分、全部命中、命中片段标亮）+ 状态开关（状态色标签 + 数量，勾选即筛选；计数与筛选是同一组控件，不再另做计数卡）+ 固定首列‘权限点’（名称在上、obj · act 在下）+ 业务列 + 全局分页（默认 10）”，默认按状态优先级再按名称排序；需要细节时点击行在 `DetailDrawer` 中查看。筛选候选项按筛选语义的对象去重——同一对象的多个来源行共享一条候选、选中后保留其全部来源行，不按行键产生重复文案（权限点按 obj · act 去重）。不得另做树视图、树/表切换或自绘计数卡。只有“对象 / 操作”两列的表格让人看不懂是什么权限，同样属于权限点列表，首列必须带权限定义名称。静态门禁拒绝业务代码自建标题为“权限点”的表格列、同时有“对象”“操作”却没有“主体”列的表格（带“主体”的是原始授权规则表；导入预览的变更对比表例外），以及业务页面引入 Ant `Tree`。
- 同构多对象比较、排序、分页或行操作用 Table；单对象异构字段用 `InformationFieldGrid`；持续阅读正文自然排版。加载、空、错与刷新反馈使用共享组件，错误不能与成功空态同时出现。**加载态全站只有一种视觉**：Ant `Spin`（经主题映射跟随前景色）——首载无内容用 `LoadingState`（`inline`/`section`/`page` 三档高度）、刷新已有内容用 `LoadingOverlay` 保留旧内容、控件与行内用 `LoadingIndicator`。禁止骨架屏：Ant `Skeleton`（含 `Skeleton.Button` 等子组件）在任何层都被静态门禁拒绝，也不得自绘 shimmer 占位块；同一页面不得混用占位屏与转圈。
- **表格列宽由列定义决定，内容跟着列走**：所有表格经共享 `Table`（`components/ui`，Ant Table 的接管层；服务端分页用它之上的 `DataTable`），它固定 `tableLayout="fixed"` 并按列宽之和算出横向最小宽度（`tableScroll`），业务不得直接用 Ant Table、不得自设 `scroll`/`tableLayout`（纵向视口传 `scrollY`）。列宽只从共享标度 `columnWidth` 取值（`id 80 / badge 120 / number 140 / time 160 / name 200 / code 240 / text 320 / long 420 / actions(n) = n×100`，全是 20 的倍数），**前端整批数据的表格必须声明展示顺序**：共享 `Table`（包括内存分页）要么传 `orderBy={(row) => 可读文案}`（按 `utils/collation` 统一比较器排，同样内容在任何地方顺序一样），要么通过 `sortable` 提供业务拖动排序，要么 `order="given"` 并注释顺序为什么有含义（命中顺序、导入预览、树形层序、拖动排序）——静态门禁强制，服务端分页的 `DataTable` 使用下述显式排序契约，由后端对完整结果排序。**表头和正文统一左对齐**：名称、标识、版本、序号、状态、时间、操作、金额、数量、比例及独立控件列全部从列起点阅读，不因列宽或内容用途改成右对齐/居中。共享 `Table` 接管表头、正文、选择列和拖动列的对齐；已有 `columnAlign.text/number/control` 用途名称作为兼容入口，均映射为左对齐。数字统一使用 `tabular-nums`，显示精度仍遵循数值格式契约。操作组在操作区域内靠右排列，表头与数据正文保持左对齐；动作组位置不改变数字和字段的阅读起点。业务不得用裸 `align` 或局部 CSS 改对齐；AST 门禁核对共享引用，浏览器门禁核对各类列的表头/正文、数值左边缘、超长数值开头与末尾均可滚动到达，以及内容更新后的对齐保持。**声明的宽度是默认值，列宽跟着内容走**：共享 `Table` 渲染后按当前页量出每列最宽的行内内容（文字、标签、按钮、行内比例值），把列调到“刚好放下”（下限是实际表头 DOM 字形宽度，取整到 20；标题测量与浏览器列宽门禁同源，不能只用缺少字距、字体拉伸等属性的 canvas 简写估计）：内容比声明窄就收紧，多余空间还给主列；内容比声明宽但仍是短内容（不超过 `text` 标度 320，如日期时间、键名、金额）就放宽到放得下——**短内容一格都不滚动**，只有超过 320 的长内容才在格内滚动。主列逐行测量（块级内容按 max-content 量），仅按不超过 320 的短内容抬高保底宽度；长内容在列内滚动，不将主列保底宽度强行抬至 320。混合短值与长值时仍保证短值完整展示，空间足够的表格不得因少数长值产生额外整表横向滚动：按常规适配后的像素总宽超过容器时，共享 `Table` 先把因少数长值放宽的列收回到“标题、该列最宽短内容、声明宽度”三者的较大值（集合、长说明等块级列最多收到 320），仍放不下则整表横滚，内容槽位跟随列宽，不另加无关的固定 max-width；**固定操作列不参与集体收缩**——它固定可见、宽度由自身动作数量与容器份额上限独立决定，文字是否收成仅图标由动作格按自身可用宽度判定（放不下才图标化、放得下恢复），不跟随“整表是否放得下”的结果。浏览器门禁覆盖混合长短值、宽屏无多余整表滚动及窄屏必要的局部横向滚动。运行时门禁 `collectCellOverflows` 检查任何单元格里不超过 288px（320 减内边距）的内容都不得出现滚动。——业务只需按内容类型选标度，不必为“这一列实际只有 chat 四个字母”逐列调宽；含块级子元素的列（操作组、集合、条件树）保持声明宽度。运行时门禁 `expectNoColumnWaste` 检查所有真实页面：声明宽度的列若全部是行内内容而列宽比最宽内容多出两个步长以上即失败（宽屏按比例摊开的部分按 表格实际宽/像素总宽 折算，主列在表头以 `data-flex-column` 标出不参与）。**每张表恰好留一列不写宽度作为主列**（名称/主体/标题，按保底宽度 `name` 计入总宽）：共享 `Table` 把各列像素宽换算成占像素总宽的百分比交给 Ant——容器比列宽之和宽时，多出的空间**按各列原宽度比例摊给每一列**（不再全堆到主列留下一片空白），容器更窄时表格以像素总宽在自身边界内横向滚动、各列回到声明宽度——长内容列不会再把后面的列挤走（静态门禁：写死数字的 `width`、没有主列或多于一个主列都拒绝；百分比宽度只用于弹窗内的对照表）。一格多项的集合（标签、权限、绑定模型）统一用共享 `InlineList`（默认按文案排序，顺序有含义时 `order="given"` 并注释原因），长说明/备注统一用共享 `LongText`：两者都只占一行、`max-width: 100%` 跟着列宽走、放不下在格内左右滚动——不折叠成 +N 或省略号（藏信息），不换行摊开（一行撑到七八行），也不给内容另定一个和列宽脱节的上限（静态门禁拒绝单元格 render 里的 `Space/Stack wrap` 标签组，以及 `description/remark/note` 列不经 `LongText`/`TallContent` 直接输出原文）。**单元格内容不折行、只在自己的列宽内**：共享 `Table` 给所有正文单元格 `white-space: nowrap` + `overflow-x: auto`——放不下的在格内左右滚动，既不折行撑高、也不溢出盖到邻列、更不省略（运行时门禁 `expectNoCellOverflows` 检查任何后代盒不越过单元格右缘）；**单元格与多行格的每一行是横向滚动槽位**：放不下在格内左右滚动、放得下不截获手势交给整张表，判断与样式由全局槽位规则统一承担（唯一来源与门禁见 [FRONTEND-TOOLTIP](03-组件与提示.md)），共享 `Table` 与业务列定义都不自行处理溢出；**纵向多行单元格（名称在上、键或 obj · act 在下，用纵向 `Stack`）按行滚动、不整格滚动**：共享 `Table` 让这类格本身不滚，每一行在列宽内各自左右滚动——放得下的标题保持不动，只有放不下的那一行（通常是长键）单独滚动，不会拖着标题一起移走；业务不得用自定义 flex 容器绕开 `Stack`；**经常要看的多行结构化内容（条件树）直接写在格内**，用共享 `TallContent` 封顶高度（`--ds-layout-cell-max-height`，120px）、超出在格内上下滚动，不折叠成“N 个字段”。**量大且平时不看的内容（JSON 备注、原始记录、关系清单）只有一种查看细则的形态：图标 + “查看”文字按钮 → 共享 `DetailDrawer`（右侧只读宽抽屉，不遮住表格上下文，左缘可拖拽调宽，无页脚、关闭即销毁）**——触发与抽屉成对时用 `DetailDrawerButton`，页面自己持有打开状态时用受控 `DetailDrawer`；不用居中弹窗、不用纯图标、不把 JSON 摊在格内。静态门禁：单元格 render 里的 `FilterRulesSummary`/`FilterRules` 必须在 `TallContent` 内，`JsonPreview` 必须在 `DetailDrawerButton` 内，`IconButton` + `EyeOutlined` 在单元格里被拒绝（跳转详情用 `ActionLink`）。
- **操作列固定为右侧尾列**：有行操作的表格通过显式 `key="action"` 声明唯一操作列，并置于列数组末尾；共享 `Table` 接管 `fixed="right"`，业务不得自行固定其他列。整表左右滚动时操作列始终可见，操作区域内所有动作完整展示，不格内滚动、不折叠菜单、不隐藏动作。共享层根据真实容器及操作格的可用宽度收起文字，仅保留图标和可访问名称；不能只按浏览器宽度判断（宽屏中的窄抽屉或面板同样需要收起）。纯只读表不添加无意义的空操作列。浏览器回归须验证滚动两端固定列位置、每个动作边界和实际点击，并验证容器扩大及同一槽位文案缩短后文字恢复。动作格观察真实结构、文案与可用宽度变化，纯行重排不得重新安装同步测量；一轮列宽测量应批量写入临时尺寸、集中读取几何，再批量恢复，避免逐格读写造成重复布局。拖放性能仍按完整生命周期的 50ms 长任务门禁验收，采样须覆盖官方落位清理、声明式顺序同步以及写请求后的刷新稳定；不得将重排或测量移到采样截止之后规避门禁。库已维护的拖动视觉状态由原生属性驱动，行组件引用只依赖其实际配置，避免状态切换或刷新重挂全部行。

- **列顺序按信息判别价值排布，不照搬实体字段顺序**：首列是记录的识别主体（名称、标题、或其与正文摘要合并的两行主列）——它是不写宽度的唯一主列；判别徽标（赞踩、启用、类型、处理状态等取值少、重复度高的徽标）紧随其后而不是占首列，读者先定位记录再判别性质；分类/标签集合随后；上下文信息（所属对象、模型、来源用户等归属与定位信息）靠后；时间等元数据列放在尾部、操作列之前；操作列固定末位。判据是“读者扫一眼最先需要什么信息判别这条记录”，纯徽标列逐行重复同样的两三个值，不作首列；用户/创建者等来源信息默认属于定位维度而靠后；与默认排序联动时，默认排序的时间列必须仍是可见真实列。审核矩阵中每张表的列顺序以读者价值复核，不以接口返回或数据模型的字段顺序照搬。**判别维度即顺序的表（拖动排序、展示顺序、执行优先级）首列是序号/拖动列**——顺序本身就是这些记录的识别主体，不需要另找名称作首列。**宿主限定维度的列在受限视图冗余**：被宿主上下文约束的维度（用户详情里的用户列、资源详情里的资源列、会话详情里的会话列）对该视图的每行取值相同，只是重复标签而非判别信息——共享组件服务于多个宿主时按宿主维度条件化隐藏该列，仅跨主体视图保留；同理该维度的列序不占用判别与内容列之前的位置。

- **列数据来自页面级请求（而不是本行记录）时，一次取回、按行查表**：如一列展示跨行共享的关联集合（“该实体的全部绑定对象”），由整张表一次分页拉满再按行分组（页面级 Hook），不在单元格组件里逐行发请求；这类列必须声明 `shouldCellUpdate: () => true`——共享 `Table` 默认只在本行记录变化时重渲染单元格，否则数据到达后格子停在加载态（开发模式 StrictMode 的额外渲染会掩盖这个问题，只在生产构建出现）。空值统一显示 `-`。
- 表格不提供多选与批量操作：写操作在行内或详情页逐条完成，业务层 Ant `Table`/`DataTable` 出现 `rowSelection` 由静态门禁拒绝。确需一次处理多条数据时由后端提供一次提交、返回计数或整体事务的接口，禁止 `Promise.all(rows.map(单条写接口))`（含数组里展开多个 `.map` 的写法），静态门禁强制（并发读取除外）。
- 服务端分页表格统一使用 `DataTable` + `useDataTable`：Hook 持有分页、排序、已提交筛选与末次请求胜出，页面只提供 `request({ current, pageSize, sort, filters })` 并把返回的 controller 交给 `DataTable`（`controller` 必须是 `useDataTable` 返回值或同页 `useXxx` Hook 解构出的成员，静态门禁强制，不得手工拼装或运行时 spread 覆盖）；与 URL 同步的页面用受控 `query`/`onQueryChange`，页面级作用域（时间范围等）用 `scope` 让表格回到第一页。`DataTable` 自身接管共享分页（默认每页 10，候选 10/20/50/100，统一总数、尺寸切换、窄屏简化）、局部横滚与 `TableQueryBoundary` 反馈。只在前端内存中分页的小型列表才直接使用共享 `Table`，由共享层接管横向滚动与表格布局，需要纵向视口时传 `scrollY`；分页必须用 `buildTablePagination` 或显式 `pagination={false}`，页面只传 current、pageSize、total、回调，不得展开配置对象或覆写展示配置。批量加载选项的 API pageSize 不属于 UI 分页。
- **框里放完整表格只用共享 `TablePanel`**（版式参照 shadcn Tasks 与 Tremor Table：这类被普遍认可的后台表格都不给表格再画一个框）：卡片标题行（`title`/`extra`）→ 查询条（`query`）→ 汇总（`summary`）→ 表格 → 分页，纵向只以 16px 间距分隔；**表格自身表头与表面同色、不画外框、无圆角**——表头是次级色文字 + 1px 底线，行间 1px 线（主题 `Table.headerBg` 使用不透明的表面色，固定尾列表头必须遮住横向滚过的其他列），因此放在卡片内边距里不会形成第二个“深色小框”；分页行是面板最后一行，不再留底部外边距；页码项去边框，选中项用 `primarySurface` 弱底（与分段项/侧栏选中同一 accent 语言），悬停弱底，条数选择器保留输入控件形态。不得把 `DataTable` 直接放进 `Card` 正文或裸放。列表页用无标题面板，详情页用带标题面板，已处于页签面板内时用 `embedded`（不再套卡片）。静态门禁：`DataTable` 的 JSX 祖先必须有 `TablePanel`。
- **URL 查询默认值只在初始化时应用一次**：受控 `query/onQueryChange` 的 URL 必须表达当前已提交条件，空值代表用户不限定；不能通过“URL 等于首次参数”反复判断初始化。默认条件需有可恢复的明确状态，清空、翻页和浏览器前进/后退后，可见已提交条件与请求条件保持一致。浏览器回归同时核对控件状态、实际请求以及历史导航，不能只断言 URL 或控件变空。

### 查询区与筛选选型

查询区统一使用共享 `QueryForm`：标签与控件同行、条件横向排列，空间不足时整项换行；≤480px 时标签独占一行、控件撑满。下拉统一使用 `FilterSelect`，不得直接使用原生 Select 或通过别名绕过。列表条件修改不立即请求，点击唯一查询按钮或回车才提交，提交回到第一页；分页、刷新、历史导航和导出沿用已提交条件。远程候选搜索与导出数量预览是独立读取，不冒充列表查询。

筛选默认**空值不限制**，清空单个条件使用控件自身清除入口。不添加“全部 / 不限 / 任意”选项、空字符串或 null 哨兵，也不加重置/清空筛选按钮。零值、false 与空值须明确区分，不能以真值判断丢失合法选项。默认条件只在初始化应用一次，清空后不得恢复隐藏限制。

| 数据语义 | 控件与取值 | 接口与候选要求 |
| --- | --- | --- |
| 可组合枚举、标签、用户、模型等离散维度 | `FilterSelect kind="enum"`，可清空、可搜索多选；空数组不限 | 同一维度 OR、不同维度 AND，后端数组参数一次查询。候选恰好一/两个也不改为单选。 |
| 启用/禁用、赞/踩、allow/deny 等完整二元状态 | `FilterSelect kind="pair"`，可清空单选 | 只有语义上完整二元划分才适用；不能因当前只有两个用户/模型就选 pair。远程实体候选不得用 pair。 |
| 决定数据集且不可缺省的作用域，如应用 ID | `FilterSelect kind="scope"`，单选不可清空 | `Form.Item` 必须有 `required: true` 校验；缺作用域不查询。分类/处理状态等可选条件不得伪装成作用域。 |
| 自由关键词、备注全文、无法枚举的值 | 可清空 `Input` / `SearchInput` | 用于文本匹配；已有稳定实体候选的字段优先选择，不要求用户记住标识再手填。匹配语义统一：作为搜索条件的模糊匹配一律大小写不敏感且用户输入的通配符按字面处理（后端统一 `sqllike.Pattern` 构造模式、`sqllike.Clause` 生成 `ILIKE ... ESCAPE E'\\'` 片段，候选检索与输入模糊同规）；已提交的筛选值（多选数组、标识、精确 ID）保持大小写敏感的精确匹配。 |
| 时间或数值范围 | 对应原生范围控件 | 可选时间可清空；导出等真正必填范围以字段校验表达，不加“全部时间”选项。 |

大候选集复用 `useRemoteOptions`：关键词防抖、有界服务端查询、末次响应胜出，已选值及其名称保留；失败在下拉内显示原始错误经共享过滤后的提示与重试，不伪装成功空态、不弹读取通知。候选来源匹配所查数据集，历史记录中的用户/停用模型不得因当前目录删除而无法筛选；不从当前分页抽候选，也不全量下载大目录。静态小集合可直接传 options。

静态候选按当前业务和接口契约定义，不因为当前页或当前数据库没有记录就删除合法类型；只有代码和接口明确不再支持的候选才移除，并同步列表范围、创建/编辑入口和回归门禁。不同表格的领域范围分别核对，不把一个页面禁止的类型机械删到其他页面。禁止为废弃类型添加历史展示或旧接口兼容分支。候选回归须同时验证废弃项不出现、合法项在空结果时仍可选择。

**选型优先级是多选 → 单选 → 自由输入，但以字段语义和接口能力为准**：可组合实体筛选（所属用户、所属分组等）必须使用多选，后端提供数组精确匹配与基于所查历史数据的有界候选；不能因旧接口只支持字符串而继续填空。完整二元状态和必填作用域保留单选，密钥片段、跨列内容全文等真正自由文本保留输入。每个 `QueryForm` 字段须以 `data-filter-column="./columns#nickname"` 绑定真实列定义（同文件写 `#字段`，支持 `@/` 路径），门禁扫描全量源码及抽出的局部查询字段组件，要求目标文件中真实存在带 `title` 与 `dataIndex/key` 的列。**凡绑定列的字段（含 keyword/range 用途）标签一律与表头使用同一文案键，不得自造筛选文案**。确属跨多列的全文搜索（如 i18n 键值、标签名称/标识/描述合并检索）才不绑定 `data-filter-column`，仅声明 `data-filter-purpose="keyword"`，标签统一使用 `common.vocab.search`，门禁同步强制；绑定单列的关键词字段必须绑定且沿用列表头文案。时间范围使用 `range`；必填作用域使用 `scope`，必须仍有 required 校验；密钥片段等必要标识搜索使用 `identifier`，绑定真实详情字段的 `key/label/value`，不能借此声明不存在的展示对象。元数据仅说明实际契约，不能代替请求与结果回归，禁止用当前分页生成候选。项目在 `design-system.project.json` 的 `entityFilterFields` 登记已核实的实体筛选，AST 按字段及实际导入绑定检查控件，拒绝退回 Input 或 pair；新增实体筛选须同时登记、核对数组请求、候选作用域、清除和分页/汇总/导出一致性。语义判断本身不能由字段名字机械推断。实体名称类字段均属于实体筛选，不得用旧字符串模糊接口或 `keyword` 标记豁免。小型完整配置接口允许从全量结果生成候选并按已选集合精确过滤；分页接口必须先提供一次数组查询，不能在当前页结果中筛选或逐值循环请求。

上游接口只提供单值或模糊搜索、不支持实体数组筛选时，对应字段保留自由搜索，并在 `scripts/design-system.project.json` 与规范中登记该限制和上游契约；不能据此豁免本仓库可修改接口上的实体字段。上游补上数组契约后应同时迁移共享多选、候选与回归。

所有支持清除的输入控件必须声明 `allowClear`，包括 DatePicker/TimePicker 的 RangePicker、Input 的 TextArea/Password/Search、Select、AutoComplete、TreeSelect、Cascader、Mentions。只有真实不可清除的必填选择可声明 `allowClear={false}` 并说明语义；可选查询不能关闭清除。InputNumber 没有该属性，不参与此项门禁。共享 FilterSelect 接管清除与模式，不允许业务覆盖。门禁解析真实导入、别名、namespace、子组件及静态 spread，拒绝运行时 spread 覆盖清除声明。

控件宽度遵循共享标度：静态下拉按最长候选量宽（120–240px，封顶查询控件宽度——个别超长候选不把触发框和整行查询区撑宽，长文本在候选槽位内横向滚动），远程实体使用查询控件宽度，弹层按内容展开；多个已选标签换行展开，不折叠为 +N；单个超长标签限制在控件内，文字进入统一滚动槽位，关闭图标保持可达。自由文本/数字/日期用 `--ds-layout-query-control-width`（240px），日期范围这类天然双值控件用检索控件宽度 `--ds-layout-control-width`（320px），溢出靠原生输入滚动查看，不用省略号。`SearchInput` 的匹配规则在尾部问号及可访问描述中。查询按钮引用 `common.actions.query`，分页文案由 Ant ConfigProvider locale 提供。

验证必须同时覆盖真实控件、提交参数和结果：选择多值、清除某值/全部、合法 false/0、分页与导出条件一致、候选搜索失败/重试及乱序响应、历史值保留、宽窄屏双语全文。静态门禁拒绝哨兵（含翻译文案、变量、spread）、没有必填校验的 scope、远程 pair、不可清空可选查询及原生下拉绕过。字段是否适合枚举、二元划分是否完整及作用域是否真实仍需按接口与调用方审核，不能只以编译通过认定选型合适。

- 查询按钮属于查询区域收尾操作，通过共享 QueryForm 自动靠右；条件换行或窄屏单列后仍靠右，不在业务页面各自加占位元素。

- **全部列头与正文共享几何边界**：普通列、数值列、选择/展开/拖动/排序辅助列及固定操作列的可见叶表头和对应正文格必须具有相同左右边界与宽度。共享 Table 同一次列定义交给 Ant 的表头和正文，不允许页面分别改 th/td 宽度或位移。整表横滚前后、明暗主题和宽窄容器都应保持同源；分离滚动表头同样适用。分组的最小总宽与比例只按递归叶列计算，组容器不得另设宽度重复计入；分组表头按 rowSpan/colSpan 的逻辑叶列对应，合并数据格按覆盖叶列的组合边界核对；Ant 测量行、空态与展开说明行不作为正常数据列。全局运行时 table-geometry 守卫逐一检查真实共享 .ds-table 的所有正常数据行，不检查第三方 iframe 内用户 HTML；回归须包含真实移动数据格的负例，确保守卫能拒绝头/正文错位。

- 固定操作格不是横向滚动槽，不应用滚动槽的透明行内边框替代内边距。除外框宽度外，门禁必须核对表头和正文 padding box 的固定阴影锚点，透明边框导致可见固定边界内移同样拒绝；保留外框相同但添加透明边框的真实 DOM 负例。


## 默认顺序与主动排序契约

默认顺序先服务于阅读目的。通知、反馈和记录按创建或发生时间倒序，最新事项先出现；创建时间必须作为真实列展示，不能藏在接口排序字段里。用户、资源、规则等实体目录按首个业务名称列自然升序，数字片段按数值比较，NULL、空字符串和纯空格名称在升序、倒序中都置后，并以稳定唯一标识作同值次序。自然顺序必须对完整结果计算后分页，不能只重排当前页。分析类列表默认按指标值倒序，排查类列表按持续天数倒序；客户端展示配置、分类选项按实际配置顺序。权限点按状态优先级再按名称，判定命中和导入预览保持原有业务顺序。排序字段与接口字段不同可以明确映射，但不能用“累计值”冒充“剩余值”。

每个业务 `DataTable` 必须内联声明 `ordering={{ column: "./columns#字段", order: "ascend", interactive: ["字段"], reason: "排序用途与不开放列的原因" }}`。同文件用 `#字段`，跨目录允许 `@/`。默认字段、主动字段均绑定实际传入的列，禁止隐藏字段、操作列、动态展开绕过、重复字段或空原因。共享层统一生成排序箭头及当前方向，业务列不得自设 `sorter`、`sortOrder` 或 `defaultSortOrder`。清除主动排序恢复该表默认顺序，切换排序回第一页，筛选及刷新保持已选顺序。

只对确有浏览用途且接口支持完整集合排序的列开放主动排序：实体目录的名称用于定位；时间列用于浏览新旧；总量、次数、均值、持续天数等单一指标用于比较；有执行语义的优先级用于检查顺序。状态、身份、类型、分组通常用筛选，标签集合、长说明、原始规则串、复合额度、动作列不开放排序。标识列不能仅因可比较而自动开启；配置拖动排序表不再加会打乱保存顺序的表头排序。开放名单由每张表真实用途决定，不要求所有列都可排序。

上游分页接口固定排序且不支持排序参数时，属于外部接口约束适配，不是通用 ID 展示豁免：页面路径、真实列文件、服务函数、endpoint、字段、倒序方向、禁止主动排序及原因逐表登记在 `scripts/design-system.project.json` 的 `externalFixedOrderTables`，静态排序门禁核对该页实际调用和列声明。仅登记合同中的实际 ID 列可见，其他页面和其他字段仍受 ID 禁令约束；注释不能代替登记，也不能仅登记原因而跳过 endpoint 校验。禁止当前页名称排序伪装完整结果自然序。该限制不能扩散到本仓库已支持排序的表格。若上游增加排序能力，需同时更新接口映射、实际列契约及跨页测试。

静态门禁追踪实际 `columns` 数组、跨文件构造函数、`useMemo` 和控制器解构返回，不能借同文件另一表的列通过校验；无法追踪的动态列来源直接拒绝。条件分支或筛掉的列由共享运行时再次核对当前实际叶列。本地验收必须确认实际服务进程来自当前源码；Vite 热更新不代表已编译后端同步更新，禁止用旧二进制的接口结果代表当前实现。多键顺序必须验证乱序插入数据在不同分页大小下拼接后的结果一致，主键、次键及稳定键不可互换。AST 元数据不证明后端排序正确：行为测试必须核对初始请求、升降切换、恢复默认、跨页稳定性以及筛选后的排序保持；接口排序字段只接受明确定义的映射，不把用户字段直接拼入 SQL。

### 全部业务表格排序审核矩阵

接入项目按上述规则维护本仓库全部业务表格的排序审核矩阵（每行：表格、默认顺序、开放的主动排序列、不开放原因），随实现同步更新并由排序门禁核对实际列与登记一致。矩阵是各项目的审核产物，安装器不预填业务行。

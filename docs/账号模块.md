# 可选账号模块

DSdocs 使用 authentik 开源版提供本地账号、密码、登录和会话。文档正文保存在 MDX 文件中，身份数据库不保存文档。authentik 原生支持简体中文，独立实例 Blueprint 默认配置 `settings.locale: zh-Hans`；文档编辑器按项目选择保留 Fumadocs 官方英文控件。

## 使用范围

| 组合               | 启动方式                    | 账号依赖           |
| ------------------ | --------------------------- | ------------------ |
| 独立读者端         | `pnpm build` 或基础 Compose | 无                 |
| 原版官方 Studio    | `pnpm studio`               | 无；默认本机入口   |
| 本地统一面板       | `pnpm manage` 或 local 配置 | 无；只显示文档页   |
| 统一面板与动态账号 | authentik 配置              | 由 authentik 提供  |
| 复用现有身份实例   | external 配置               | 不再启动身份数据库 |

不使用账号体系时，无需设置任何身份环境变量，也不加载身份服务。可以继续使用自己的访问入口保护管理服务。

所有 editors 成员都能编辑整个工作区，也能在统一面板管理 DSdocs 本地编辑账号；不再区分文档权限。这里适合互相信任的维护团队。authentik 的系统管理员另外负责身份基础配置，普通编辑者不会获得它的超级用户身份。

## 本机无账号运行

```sh
docker compose -f compose.yaml -f deploy/compose.local.yaml up --build -d
```

管理入口默认 `http://127.0.0.1:5182`，仅绑定回环地址。不要通过另一个公开代理直接放行。容器写入宿主机内容目录，需为 node 用户提供目录写权限；不要改成全员可写。

## 新建独立身份实例

选择 `deploy/compose.authentik.yaml`，通过私有运行环境设置：

| 变量                                  | 用途                                                            |
| ------------------------------------- | --------------------------------------------------------------- |
| `DSDOCS_IDENTITY_DB_PASSWORD`         | 随机数据库口令                                                  |
| `DSDOCS_IDENTITY_SECRET_KEY`          | 独立随机会话密钥                                                |
| `DSDOCS_IDENTITY_API_TOKEN`           | 独立随机 API 令牌，由 Blueprint 创建服务账号绑定，只留服务端    |
| `DSDOCS_IDENTITY_ADMIN_PASSWORD_HASH` | 可选，首次初始化 akadmin 的 Django 密码哈希                     |
| `DSDOCS_EDITOR_URL`                   | 浏览器访问的编辑器完整 URL，默认 `http://editor.localhost:5181` |
| `DSDOCS_IDENTITY_URL`                 | 浏览器访问的身份服务完整 URL，默认 `http://auth.localhost:9000` |

凭据不写进仓库、命令历史或前端配置。需要初始密码哈希时，用官方 `hash_password` 命令交互输入；没有设置初始哈希时，使用 authentik 原生首次设置页面 `/if/flow/initial-setup/`。邮件恢复需要另行配置 SMTP。

```sh
docker compose -f compose.yaml -f deploy/compose.authentik.yaml up --build -d
```

本地编辑入口为 `http://editor.localhost:5181`，身份管理入口为 `http://auth.localhost:9000/if/admin/`。正式环境需要 HTTPS、实际域名、入口转发和持久化备份；不要原样把 HTTP 测试入口暴露公网。示例不映射 PostgreSQL 或管理服务端口，不挂载 Docker socket，采用官方内嵌 Outpost。

Blueprint 创建 editors 组、应用、Proxy Provider、服务账号及其有限 API 权限。首次使用时，由系统管理员在 authentik 创建一个普通用户并设置密码，将其加入 editors。以后可在统一面板创建、启停账号和重置密码。没有默认编辑口令，不把所有现有用户自动加入编辑组。

Blueprint 面向独立实例，会设置默认品牌语言和 embedded outpost 的 provider 列表；不要挂到已有共享实例覆盖其他应用。

## 统一面板的账号范围

界面只显示路径精确为 `dsdocs` 的 internal 用户。通过统一面板创建的账号会自动使用该路径并加入 editors。其他管理员、外部和服务账号不显示，也不能经该接口修改。需要纳管旧账号时，由身份管理员确认身份后在原生后台将路径设为 dsdocs；不要搬入系统账号。

创建时先保存为停用，设置密码、完成组授权后才启用。中途失败可能留下停用账号，管理员可在原生后台修复或删除。重新启用会补齐 editors 授权。不能在统一面板停用当前登录账号，以免误锁自身；删除、系统会话撤销等运维操作使用 authentik 原生后台。

服务端令牌只授予查看、创建、修改用户、重置密码、查看组和加入组的权限，未授予超级用户、角色分配或删除权限。这些仍是较高权限的身份 API 能力，必须保护令牌和私有管理服务。API 适配检查用户范围、字段、来源和请求大小；认证代理删除外部身份头后注入可信身份，不能绕开代理直接开放管理端口。

## 复用现有 authentik

使用 `deploy/compose.authentik.external.yaml`，设置 `DSDOCS_IDENTITY_UPSTREAM` 为代理可访问的 authentik 地址，`DSDOCS_IDENTITY_API_URL` 为管理服务可访问的 API 地址，并配置受保护的 `DSDOCS_IDENTITY_API_TOKEN` 与 `DSDOCS_EDITOR_URL`。

在现有身份后台按官方配置创建单应用 Forward Auth Provider、绑定 editors 组，并将 Provider 加到已有 Outpost，保留其他应用。为服务账号授予上述公开 API 权限，使用专用令牌。不加载本仓库的身份 Blueprint，不重复启动数据库和 worker。默认语言在现有品牌属性中设置 `settings.locale: zh-Hans`。

```sh
docker compose -f compose.yaml -f deploy/compose.authentik.external.yaml up --build -d
```

其他身份服务可以替换，但必须提供同等应用准入、完整 HTTP/WebSocket 保护；账号 UI 适配目前明确针对 authentik API v3，不宣称任意身份服务零改动兼容。

## 会话、撤权与故障

入口对 HTTP 和 WebSocket 握手鉴权。Caddy 的 `stream_timeout 30s` 促使持续连接重建，但身份缓存和刷新仍由 authentik 决定，不能据此承诺 30 秒内撤权。禁用、组成员变更、主动退出和现有连接需分别验收。已下载内容不能远程抹除，撤权重点是阻止后续服务端读取和保存。

身份服务故障时入口应拒绝访问，不降级为匿名。公开 `/docs` 不经过账号模块。任何部署的撤权时效以该环境测量为准，不把一次本地观测写成保证上限。

## 本地验收

`pnpm test:management` 在临时文件工作区验证不带账号的统一面板；`pnpm test:identity` 使用独立 Chrome 上下文验证真实登录与账号操作。后者只针对隔离身份实例，必须提供仓库外的 `DSDOCS_IDENTITY_TEST_CREDENTIALS` JSON 路径和 `DSDOCS_ARTIFACTS`。JSON 包含既有编辑用户的 username、password、id，以及一个不得修改的外部身份 foreignId，用来验证范围拒绝；nonEditor 提供另一个未加入 editors 的普通测试账号 username、password 和 id，用来验证没有后台权限时拒绝访问。不要使用生产账号或生产数据库。

测试会创建带 browser 前缀的账号，结束时停用；隔离测试库由测试环境统一销毁。凭据和会话文件权限设为仅当前用户可读，不提交或输出到日志。
